# 04 视觉与标定

> **一句话概括**：视觉只做两件事 —— 用 **`mode="ring"` 找同心圆环的中心**（加工区标靶）、用 **`mode="color"` 找实心色块的质心**（原料区取料）；两者共用同一套预处理、坐标系与滤波。
> **模式选错、或把滤波"旧中心保持"当真，都会得到"零修正的假收敛"** —— 这是踩过最大的两个坑。瞄准侧是"三阶段 X1→Y→X2 + 分段限幅 + 近中心软化 + 翻转阻尼 + 按 K 换算脉冲"的闭环，K 值必须**本车实测**。

## 1. 两种检测模式（★最核心）

### 1.1 对照表

| 维度 | `mode="ring"`（圆环中心） | `mode="color"`（实心色块质心） |
|---|---|---|
| 入口 | `RingVision.locate()` → `RingDetector.process()` | `ColorVision.track()` → `ColorBlobDetector.detect()` |
| 算法 | 灰度 → 自适应二值(`thr_block/thr_c`) → **闭运算 `close_k` 接断线** → 最大连通域 → **最小外接圆**，圆心即靶心（无霍夫/无聚类） | HSV/chroma 阈值 → 掩膜 → 形态学(`k_open/k_close`) → 轮廓 → **质心 + 等效半径** |
| 形状判据 | `min_area_frac`（CALIB 默认 0.001）+ `r ≤ 0.5·min(h,w)`（`find_center`） | `min_area_frac`/`max_area_frac`/**`circ_min`**（`vision.ColorVision` 默认 0.0008/0.60/**0.45**） |
| 额外输出 | `digit`(1/2/3)、`digit_score`、`n_rings` | `circ`(4πA/P²)、`fill`、`score`、`area_frac` |
| 服务对象 | **加工区标靶**（同心虚线圆环、中间是空的） | **原料区取料**（实心彩色方块/圆块） |
| 调用方 | `Aim.locate(mode="ring")`（`target_mode` 默认 ring） | `Aim.locate(mode="color", color="red"/"green"/"blue")` |

两种模式返回**同一结构** `{found, cx, cy, r, digit, conf, stale, shape, frame}`、坐标系一致 → 下游的分轴收敛、限幅、偏移回放完全不用改（见 `Aim.locate()` docstring）。

### 1.2 ⚠️ 标靶是"同心虚线圆环"，用 color 模式必然失败（★最大的坑）

**现象**：加工区三个靶位全部报"收敛 ✓"，但 `offset` 全是 `{'base':0,'arm':0}` —— **一个动作都没发**。
**链条**（证据见 `README.md` 的 2026-09-18 条目、[place_demo.py](整机程序设计/VisualBot2/place_demo.py) 的 `do_aim_target`）：① `do_aim_target` 传的是**颜色名** → 走 `mode="color"`（找**实心色块**质心的算法）；② 目标却是空心同心虚线环 → 填充率 `fill=A/πr²` 与圆度 `circ` 过不了 `circ_min=0.45` → **每帧都 `found=False`**；③ `BlobTracker` 的 stale 保持把**上一轮的旧中心**当 `found=True` 返回（§2）；④ 上层据旧位置算出 `dx=-2.9/dy=+6.3`，都在容差 8px 内 → **三阶段各一拍"达标"** → 假收敛。
**证据与修法**：诊断帧 `aim_fail/T2_213400_raw.jpg` 里标靶是清晰的红/绿/蓝同心圆环（`Aim._dump_fail` 保存）；① 加工区改 `mode="ring"`，② `aim.py` 加通用防假收敛（`AIM_STALE_GIVEUP`，§2.3）。**修后实测** `offset={'base':-178,'arm':-212}`，一拍修掉 `dx=+64`。

> 规矩：**"标靶是环"就用 ring 找圆心，"料是实心块"就用 color 找质心，不能互换。** `place_demo.TARGET_COLOR`（1 红/2 绿/3 蓝）现在**只用于日志与颜色一致性检查**，不参与定位。

### 1.3 `close_k` 为什么关键

`close_k` = 闭运算椭圆核尺寸，物理含义 **≈ 相邻环线在画面里的间距**：虚线同心环的每小段本是**独立连通域** → 最大连通域只能圈住中心那个小圆 → 标靶偏一点、或几段虚线被反光吃掉就丢目标（车主反馈的"识别灵敏度太低"就是这个）；如果 `close_k` 够大，闭运算就把虚线**连成一条实心环带** → 最大连通域 = 整条外环带 → 最小外接圆的圆心就是靶心。

| 来源 | 值 | 说明 |
|---|---|---|
| `ring_center_detect_v2.CALIB["close_k"]` | **9** | 上游库默认，按环线间距定 |
| `PERF_PRESETS["rdk"]["cfg"]["close_k"]` | **5** | rdk 档**覆盖**成 5（省算力，注释称"精度与 41/9 一致"） |
| `ring_calib.json` 里若存了 `close_k` | 存什么用什么 | 档案在性能档**之后**合并，会覆盖档位值 |
| `target_stream_ui.py` 的 `_tune` | **9** | 彩色标靶台里 `k_close=9` 被特别标注为"**关键**" |

> ⚠️ **当前实际生效的是 5**：`ring_calib.json` 里只有 `rotate_ccw`/`rotate_mode` 两项（见 [doc/README.md](整机程序设计/VisualBot2/doc/README.md) 已知问题）。想要 9 就得在 `ring_stream_ui` 面板把 `close_k` 调到 9 并**点"保存档案"**。

### 1.4 `center_gate_r`：多靶位同框只认画面中心那个

`RingDetector.process()` 的位置门（`CALIB["center_gate_r"]` 默认 **200** px）：`np.hypot(cx-fw/2, cy-fh/2) > 200` 就直接 `self._lost(cfg)`（等价"这帧没找到"）。作用：加工区三个靶位可能同时入镜，没有这道门就可能锁定旁边的靶 → 瞄准越修越偏。离线单图调试会把它设 0（`ring_stream_ui.py` 的 `--image` 分支）。

### 1.5 选模式的规矩

`Aim(..., target_mode="ring")` 是默认；取料调 `aim.converge(mode="color", color="green")`，放置调 `aim.converge(mode="ring")`。`ColorVision.track()` 会把 `circ`/`fill`/`area_frac` 一并透传，用来判断"套住的到底是不是那块圆料"（现场症状：标定时 `r` 异常偏大、两个方向同向 —— 就是套错了目标）。

## 2. `BlobTracker` 的 stale 保持（★第二个大坑）

### 2.1 行为：连续丢失 ≤ `stale_max` 帧会"假装找到了"

`vision.BlobTracker.update(raw)`，当 `raw["found"]=False`：

```python
self.stale += 1
if self.cx is not None and self.stale <= self.stale_max:      # stale_max = COLOR_STALE_MAX = 10
    return {"found": True, "cx": self.cx, "cy": self.cy, "r": self.r, "conf": 0.5,
            "raw": (self.cx, self.cy), "stale": self.stale, "held": True}
```

即 **`found=True`、坐标 = 上一轮中心、`conf=0.5`、`held=True`、`stale=N`**。本意是偶发丢一帧时闭环别立刻放弃，代价是**上层不设防就会拿到过期坐标**。
> 对比：**ring 路径不会这样** —— `RingDetector._lost()` 返回 `found=False`，`vision.locate()` 出来就是 `found=False`，`converge` 走"未找到目标"分支。**假收敛只出现在颜色路径**（`ColorVision.track()` → `BlobTracker`）。

### 2.2 假收敛链条

```
检测不到目标（阈值/形状判据不过）→ BlobTracker 返回 found=True + 旧中心 + held=True
  → converge 算出 dx/dy ≈ 0（旧中心本就靠近画面中心）→ 三阶段各一拍"达标"
  → 返回 ok=True, offset={'base':0,'arm':0} → 上层以为瞄好了，实际一个脉冲都没发
```

### 2.3 防护：`AIM_STALE_GIVEUP`（通用，与模式无关）

```python
_st = int(loc.get("stale", 0) or 0)
if _st > 0 or loc.get("held"):
    stale_run += 1                 # 这一拍既不判断也不动作，等真实检测
    if stale_run >= int(getattr(SC, "AIM_STALE_GIVEUP", 6) or 6):
        self._dump_fail(tag, loc, color); break      # 明确放弃 + 存诊断帧
    time.sleep(self.settle_s); continue
stale_run = 0
```

含义：**只要视觉一时看不到目标，就不允许给出"瞄准好了"的结论**。连续 `AIM_STALE_GIVEUP`（默认 **6**）拍仍只有旧中心 → 放弃并落盘诊断帧。

### 2.4 开工预热 `AIM_WARMUP_FRAMES`：治"第一拍方向是反的"

第一拍不可信的两个来源：① 上一动作刚停、机械余振/曝光未稳；② stale 保持给的旧中心。`converge` 开工先丢帧，判据是 **`found` 且 `stale == 0`**：

| 参数 | grab_demo（运行时） | school_config | 说明 |
|---|---|---|---|
| `AIM_WARMUP_FRAMES` | 3 | 0 | 只是**上限**，第 1 帧真检测到就放行（≈0.55s） |
| `AIM_WARMUP_JITTER_PX` | 0.0 | 0.0 | 0 = 不检查帧间抖动（抖动至少两帧才算得出，会把预热拖长一倍） |
| `AIM_WARMUP_SETTLE_S` | 0.5 | 0.5 | 预热帧间隔；**故意与 `AIM_SETTLE_S` 脱钩** |

> ⚠️ 别用"方向反了"去猜符号：`AIM_FLIP_BASE/ARM` 的实测结论是**都保持 False**，那次"一开始朝反方向走"是**第一拍数据不可信**。判方向用菜单 `c 200`（§6.1）。

### 2.5 取料侧滤波（`COLOR_*`）

顺序 **中值滤波 → EMA**（`BlobTracker.update`），另有突跳清窗：`COLOR_MED_N=3`（最近 N 帧原始中心的逐分量中值，对偶发跳变几乎免疫、滞后约 1 帧）→ `COLOR_EMA=0.35`（越小越平滑、滞后越大）→ `COLOR_JUMP_PX=90`（原始中心偏离平滑中心超过它视为换目标，直接跳过去并清中值窗）；`COLOR_STALE_MAX=10` 就是 §2.1 的 stale 保持帧数。圆环侧同类参数在 `ring_center_detect_v2.CALIB`：`ema=0.5`、`jump_px=120`、`stale_max=10`（语义对齐）。

## 3. 画面方向：三个来源与优先级

### 3.1 `cam_rotate.resolve()` 的判定顺序

```python
def resolve(rotate=None, calib_mode=None, calib_default=False):
    if rotate not in (None, "", "auto", "auto-detect"):
        return norm_mode(rotate, default="none")     # ① 显式参数最高
    if calib_mode: return norm_mode(calib_mode, default="none")   # ② 档案 ring_calib.json
    return "ccw" if calib_default else "none"        # ③ CALIB 常量（旧默认）
```

| 优先级 | 来源 | 字段 |
|---|---|---|
| 高 | **显式参数** | `CAM_ROTATE`（`route_main.py`/`grab_demo.py` 参数区）、`--work-rotate`、`RingVision(rotate=...)` |
| 中 | **`ring_calib.json`** | `rotate_mode`（优先）→ 否则 `rotate_ccw` 布尔 → `ccw`/`none` |
| 低 | **`ring_center_detect_v2.CALIB["rotate_ccw"]`** | 库常量，**默认 `True`**（树莓派时代相机倒装） |

四种模式：`none` / `ccw`(逆时针 90°) / `cw`(顺时针 90°) / `180`；别名见 `cam_rotate._ALIAS`。调参台/监控台点一次方向会 `save_mode()` 写进 `ring_calib.json`（保留其它键），供 `CAM_ROTATE="auto"` 跟随。

### 3.2 ⚠️ 部署目录没有档案时，`auto` 会回落到"转 90°"

`/root/VisualBot2` 下**没有 `ring_calib.json`** → `resolve("auto")` 落到 ③ → `CALIB["rotate_ccw"]=True` → 画面被逆时针转 90°：1280×720 变 **720×1280 竖图**（现场日志 `cx≈360/cy≈653` 反推出画面中心 360×640）；而 `K_BASE/K_ARM` 是**按 none（原图）**换算的 → 原图 +x 变成画面 ±y → **x/y 轴整个对调** → base 实际在修 `cy`、arm 实际在修 `cx` → 两轴互相拆台 → `!! 未收敛`（"瞄准越修越偏"）。

### 3.3 现状：钉死 `"none"`

| 文件 | `CAM_ROTATE` | 备注 |
|---|---|---|
| [route_main.py](整机程序设计/VisualBot2/route_main.py#L134) | **`"none"`** | 注释原文"★★画面方向：**显式 none，别用 auto**" |
| [grab_demo.py](整机程序设计/VisualBot2/grab_demo.py#L251) | **`"none"`** | 含 2026-09-17 现场根因记录 |
| [school_main.py](整机程序设计/校赛/school_main.py#L125) | `"auto"` | 校赛版主程序**仍是 auto** ⚠️ |

⚠️ **待确认**：`school_main.py` 的 `auto` 依赖"部署目录存在 `ring_calib.json`"；把它的参数区照抄到没有档案的目录就会重演 §3.2。另有一道保险：`build_car()` 会检查 `car.vision.rotate_mode`，**实际方向不是 none 就告警**。

### 4.3 `open_camera()` 的 v4l2-ctl 兜底 + 读回校验

实测（RDK X5 + LRCP G720P）：**OpenCV 锁不住这台 UVC**（设完 `auto_exposure` 仍是 3=Aperture Priority、`exposure_time_absolute` 标 `inactive`）。所以 ① OpenCV 先设 → 再用 `v4l2-ctl -c auto_exposure=1 -c exposure_time_absolute=N` 兜底；② **读回校验**：只认 `v4l2-ctl --get-ctrl auto_exposure` 回来 `1`(Manual) 才算锁上，否则打印 `[warn] 曝光没锁上`。
其它约定：`lock=True` 但**没给 exposure** 就**不乱锁**（提示保持自动）；`lock_wb` 默认关闭（部分 UVC 不支持红蓝增益，锁了发青）；打不开会**静默回退扫 0..3** → 日志里"请求 video0"不等于实际用了 video0，看 `[cam] 使用 /dev/videoN` 那行。

### 4.4 取"最新"一帧：`grab()` 抽干 + `CAM_FLUSH_FRAMES`

`CAP_PROP_BUFFERSIZE` 取 **2**（`=1` 会让驱动无法流水线，取流被砍到 **15.0 FPS**；`=2` 回到 30.0 FPS，代价约 1 帧延迟）。⚠️ **绝不在这里改分辨率** —— 分辨率一变 `K_PX2STEP_*` 全失效。`RingVision.grab()` 先用 `cap.grab()`（只抓不解码）把队列**抽干**，再 `cap.retrieve()` 取**最新**帧，抽几帧由 `CAM_FLUSH_FRAMES`（默认 **4**）控制，失败自动退回 `cap.read()`。
> 为什么必须：`cap.read()` 返回队列里**最旧**的一帧，而瞄准每拍才读一次（settle 0.65s）、相机 30fps 一直产帧 → 画面比现实晚 **2~3 拍** → 控制器以为"还没到位"继续发脉冲，机械早到位/已冲过头 → 过冲、反向、振荡。现场日志特征：`#1~#3` 的 `dx` **纹丝不动**，然后一路冲过 0 再回头。另有 `AIM_READ_FRAMES`（默认 2）：一个决策拍**连采几帧**，让中值/EMA 追上当前真实位置。

## 5. 瞄准控制律

### 5.1 三阶段 `X1 → Y → X2`

```python
STAGES = (("x", AXIS_BASE), ("y", AXIS_ARM), ("x", AXIS_BASE))   # 轴：base=4，arm=1
```

① **X1** 只用 base 收敛画面 **x**，连续 `AIM_STAGE_CONFIRM` 拍 `|dx| ≤ tol` 才算达标；② **Y** 只用伸缩收敛画面 **y**，同上；③ **X2** 再用 base 把 **x 复校回中**（②动伸缩会轻微扰动 x）。与旧实现（`base,arm,base` **每拍交替**）的区别：交替时每 3 拍只有 2 拍在修同一个轴 → 等效速度只有 2/3，且日志上 x/y 跳动、看不出卡在哪；分阶段后可**连续修**一个轴，每阶段只盯一个误差，好判断好调参。
每拍流程（`Aim.converge()`）：预热 → 取帧（`AIM_READ_FRAMES` 帧）→ `found` 判断 → **stale/held 闸**（§2.3）→ 颜色确认（仅 ring 模式带 `want_color`）→ 算 `dx/dy` → 本阶段达标判断 → 否则算限幅与脉冲并下发。退出条件：`timeout = SC.T_AIM`（school_config 20s、`school_main.py` 30s）或 `AIM_MAX_ITER` 拍。
> ⚠️ **注释与代码不一致**：`AIM_TOL_PX` 注释写"连续 2 帧"，代码用的是 `AIM_STAGE_CONFIRM`（**默认 1**）→ 以代码为准（取 1 是刻意的，误判由最后的 X2 兜底）。

### 5.2 `_target_px()`：目标点 = 画面中心 + 夹爪补偿

`_target_px()` 取 `loc["shape"]` 的 `h/w`（来自**旋转(+缩放)之后**那一帧，所以画面中心与 `locate()` 坐标系天然一致），返回 `(w/2 + SC.CAM_GRIP_OFFSET_X, h/2 + SC.CAM_GRIP_OFFSET_Y)`。`CAM_GRIP_OFFSET_X/Y` 是"夹爪与光轴不共轴"的**像素**补偿、**取料与放置共用同一对值**；语义（沿用老工程 [aim_and_place.py](整机程序设计/aim_and_place.py#L154)）：正 X = 夹爪偏右、正 Y = 夹爪偏下。⚠️ **当前三处都是 `0.0`**（school_config / school_main / grab_demo）→ 实测有偏差必须现场补值；**未找到自动化标定脚本，⚠️ 待确认**（老工程同样是手填）。

### 5.3 一拍的四级加工（★要讲透）

```python
limit_px = _stage_limit(abs(err_now), comp) * self._damp(comp, err_now)
kx = _k_scaled(SC.K_PX2STEP_BASE, r_now)          # comp == "x"
d, pulses = self._steps_for(_soften(dx), kx, limit_px)
d = _maybe_flip(d, "BASE")                        # ARM 同理
self._apply(AXIS_BASE, d, pulses, kx, +1); off["base"] += ...
```

| 环节 | 函数 | 干什么 | 默认值 |
|---|---|---|---|
| ① 分段限幅 | `_stage_limit` | 误差越大步子越大；**arm 档再乘一个缩放** | `AIM_LIMIT_STAGES=[(50,9999),(28,34),(16,19),(10,11)]`，都不满足用 `AIM_OUT_MAX_PX=9`；`AIM_ARM_LIMIT_SCALE=0.8` |
| ② 近中心软化 | `_soften` | 进入软化区只走 `AIM_SOFT_GAIN` 比例 → **一步跨不过容差** | `AIM_SOFT_ZONE_PX=10.0`、`AIM_SOFT_GAIN=0.7` |
| ③ 翻转阻尼 | `_damp` | 同轴误差**符号反复翻转**（= 上一拍冲过头）→ 步子减半，上限 `1/2^N`；连续同号立刻恢复 1 | base `AIM_DAMP_MAX_FLIP=2`(1/4)、arm `AIM_DAMP_MAX_FLIP_ARM=3`(1/8) |
| ④ 换算脉冲 | `_steps_for` | `want = -delta/k`，按 `out_max_px/k` 限幅，`pulses=round(|want|)`，`dir=FWD if want>0 else REV` | `k` 见 §5.4 |

补充：`_k_scaled(k, r_px)` 是"按目标半径（≈距离）加权 K"（`K_eff = K × r/K_R_REF`，由 `K_R_SCALE` 开关控制）；`_maybe_flip(d, which)` 读 `AIM_FLIP_BASE/AIM_FLIP_ARM`（当前都 `False`）；`_apply()` 下发后 `time.sleep(self.settle_s)`（`AIM_SETTLE_S=0.65`）—— 机械余振没停就读帧 = 基于假信息决策。**软化为什么有效**（`_soften` docstring 的离线仿真，起点 dy=+30、容差 8px、实际 K 比配置大 60%）：不软化 `[30,10.8,-6.5]`（从 +10.8 一步跨到 -6.5，**跨中心 17px**）；软化后 `[30,10.8,2.2]`（收敛且拍数不增加）。

### 5.4 K 值（px/脉冲）★必须本车实测

| 来源 | `K_BASE` | `K_ARM` | 备注 |
|---|---|---|---|
| **grab_demo.py（运行时生效）** | **0.3605** | **0.0716** | 2026-09-18 第二次干净标定 |
| 旧值 | 0.4049 | 0.0717 | 上一次标定 |
| school_main.py（本车首次，人工换算） | 0.213 | 0.0385 | `calibrate_aim.py` 转 90° 后手工换算 |
| school_config.py（老师那台车） | 0.2593 | 0.0413 | 换车/换相机安装**必须重测** |

- 单位约定：**脉冲 → 画面像素位移，正转(dir=0)让画面内容向 +x/+y 移动**（`aim.py` 文件头）。原始数据：base 400 脉冲 FWD **+141.5**px / REV **-146.9**px；arm 1500 脉冲 FWD **+108.6**px / REV **-106.4**px；耦合 base→y=+0.05、arm→x=+0.02（±0.05 内）→ **分轴解耦成立**。
- **`K_R_SCALE = False`（grab_demo 已关）**：两次干净标定给出 `r=112.7→K=0.4049`、`r=135.5→K=0.3605`，**r 变大 K 反而变小**，与"近处同脉冲位移更大"相反 —— 根因是那个 `r` 是"红色区域**总面积等效半径**"、**把同心圆环也算进去了**（外接框 452px），"检测到几圈环"随曝光/阈值变 → **r 在两次测量间不可比**，按它加权是**引入**误差。`K_R_REF` 留着（grab_demo 135.0 / school_config 114.0）。⚠️ **待确认**：`school_config.py` 的 `K_R_SCALE = True` 是默认值、被参数区覆盖成 False，不一致时以参数区为准。

### 5.5 `replay()`：偏移回放

`converge()` 返回 `off = {"base": 累计脉冲(带符号), "arm": 累计脉冲(带符号)}`；`replay(off, sign)` 按轴逐条下发：`sign=-1` → 回**观察位**（夹料的确定起点）；`sign=+1` → 回**靶心**（可放料）。这正是 `place_mission()`（`converge → replay(-1) → BUILTIN_GRAB_VEH → replay(+1) → BUILTIN_PLACE`）与 `place_demo` 的工序骨架。**为什么必须归零**：瞄准会用**伸缩**修画面 y（offset 常有几百脉冲），而动作组里的 `arm_in` 是**相对**位移 → 不归零每次落点都不同，还可能撞物架。

### 5.6 参数调优史（"瞄准很慢"的提速）

| 阶段 | 限幅形态 | 120px 初始偏差的代价 |
|---|---|---|
| 起点 | 每拍一律 `AIM_OUT_MAX_PX=12` | 11 拍 ≈ 9.4s |
| 第一次分段 | 旧表 `[(60,45),(25,20)]` + arm 缩放 0.5 + 软化 zone20/gain0.5 + damp 4 | 三阶段合计约 9 拍（≈13s，车主实测"很卡"）⚠️ 与口头"≈16s"略有出入，以文件中的 13s 为准 |
| **现在** | `>50px` **全额**（`9999`，按 K 一步走够）+ 软化 zone10/gain0.7 + damp base 1/4·arm 1/8 + arm 缩放 0.8 | **1~2 拍/阶段** |

> 关键教训：限幅是**四层叠加**（分段表 × arm 缩放 × 软化 × 阻尼），任何一层收紧都会把总步长压成"每次只修一点点"；曾有一次 `AIM_LIMIT_STAGES` **不在 `AIM_KEYS` 里** → 参数区改了根本不生效（`k` 命令查看还会显示新值），已修。

## 6. 标定流程（照着做）

**顺序**：硬件/曝光 → 圆环阈值 → 颜色阈值 → K 值 → 夹爪偏移 → 存档案 → 联调。每步先"看画面确认能稳定检出"再往下走；标定前**先张爪**（`grip_open`），否则爪片挡在镜头前会把色块切掉甚至自己被当成目标。

### 6.1 测 K（发固定脉冲、量画面位移）

用 `grab_demo.py` 菜单命令 **`c <base脉冲> <arm脉冲>`**（`couple_calib`）：`c 200 800`（base 200≈43px、arm 800≈31px 才够信号）；2026-09-18 用的是 `c 400 1500`。它做四件事：① 张爪 → ② 取起点（4 帧平均）→ ③ base 正/反转各一次、arm 正/反转各一次（**每步停 1.8s 后取 4 帧平均**）→ ④ 折算 px/脉冲 + 查耦合 + 判方向。

| 判据 | 期望 | 不满足说明 |
|---|---|---|
| 同轴 FWD/REV | **一正一负、大小接近** | 两步读到同一中间态 → 加大脉冲重测 |
| 回位误差（REV 后离起点） | ≤ 15px | 没等停稳就读，或机械回差大 |
| 信号强度 | `\|K\|×脉冲 ≥ 8px` | 会被噪声主导 → 加大脉冲（base 200~400、arm 800~1500） |
| 耦合 | base→y、arm→x 都在 **±0.05** 内 | 分轴解耦不成立，先查是否套错目标（张爪/曝光） |
| 方向 | `c 200` 打印"正转让 cx 变大还是变小" | 与假设不符才翻 `AIM_FLIP_BASE/ARM` |

⚠️ **不要直接抄 `calibrate_aim.py` 的建议值**：它内部用老工程的 `CALIB(rotate_ccw=True)` 把画面**逆时针转 90°**，坐标轴与主程序（`none`）差 90°，算出的 K 只有真值的 1/20~1/30（`school_main.py` 那段人工换算就是这么来的）；`c` 命令走**主程序自己的相机与坐标系**，量出来直接可用。⚠️ **必须在实际瞄准那个距离上测**（K 随距离变），测完把当时的 `r` 记进 `K_R_REF`。

## 7. 数字识别（环心 1/2/3）

- 上游 `ring_center_detect_v2.recognize_digit()`：裁剪**严格限制在最内环 φ1 之内**（`digit_inner_frac=0.80`，找不到 φ1 时回退 `inner_fallback_frac=0.55`），这样环线（实线/虚线）进不了裁剪区、不会被误当数字。
- 模板：`_build_rot_templates(step)` 渲染 **3 个数字 × 4 种 Hershey 字体 × 3 种粗细 × 每 `digit_rot_step`(5°) 一张** = **2592 个模板**，与裁剪字形做 NCC（低于 `digit_thr=0.42` 视为未识别）；稳定性靠最近 `digit_votes=20` 次高置信读数**取众数**，环连续丢失超过 `digit_unlock_stale=15` 帧或 `jump_px=120` 判为换环时**清空窗口**。
- 现场补模板：[digit_templates_ext.py](整机程序设计/VisualBot2/digit_templates_ext.py) 的 `install()` 把 `digit_custom/<1|2|3>/*.png`（紧致二值字形）按同样步长生成模板并与内置库**合并**，在打印体/现场字体上更准（`install()` 幂等、`add_crop()` 一键存样重建）。
- **节流** `digit_every`：每 N 帧才做一次 NCC（默认 1 = 每帧，rdk 档 **3**）；校赛主程序把 `DIGIT_EVERY` 设成 **999**（= 关掉）以省算力（`school_main.py` 注入 `car.vision.cfg["digit_every"]`）。
