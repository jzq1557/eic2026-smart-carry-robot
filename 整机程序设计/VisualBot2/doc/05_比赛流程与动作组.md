# 05 比赛流程与动作组（交接文档）

**一句话概括**：`route_main.py` 把一场比赛拆成**七段跑图**（`s1_out` … `s7_finish`，登记在 `STAGES`），第 ② 段读二维码拿到任务码 `"123+321"`，第 ③ 段进原料区按**前段顺序**在 1/2/3 号位取三块料放到车上物架，第 ⑥ 段进加工区按**后段顺序**（经 `PLACEMENT_MAP` 换算成靶位）把三块料放到标靶上；所有机械动作都是**动作组**（`("轴/别名", 脉冲, 速度)` 的列表，可带 `("par", [...])` 并行子步），由 `grab_demo.py`（原料区取料 + 放物架）与 `place_demo.py`（加工区从物架取料 + 放置）提供。

> 本文只描述代码现状。凡代码注释与代码值冲突处，一律**以代码值为准**并标 ⚠️。

## 1. 赛题与任务码

- 任务（`route_main.py` 模块 docstring）：原料区按任务码取 3 个物料 → 加工区按规则放到 3 个标靶上。
- 任务码（`school_config.py` 的 `CODE_RE` / `parse_code()`）：`"123+321"` —— 前段 3 位 = **取料顺序**，后段 3 位 = **放置顺序**；数字 = 颜色编号，`COLOR_OF = {"1":"red","2":"green","3":"blue"}`。
- 兜底码 `CODE_DEFAULT = "123+321"`（扫码超时或码不合法时用，会打告警）；读到的码必须上屏（赛规），走 `car.show_qr(code)`（见 `s2_scan()`）。
- 取料位置：物料编号 **i** 就在原料区 **i 号位**（编号与物理位置一一对应，见 `s3_material()` 的 `MATERIAL_CM[int(mid)]`）。物架归置：红→1 号架 / 绿→2 号架 / 蓝→3 号架（`RACK_OF_COLOR`）。
- 解析入口：`pick, place = SC.parse_code(code)`（不合法返回 `(None, None)`，两处调用方都退回 `CODE_DEFAULT` 重解析）；`plan = SC.place_plan(place)` = `[(物料号, 靶位号), …]`，见 §5。

## 2. 七段跑图逐段说明

段表本体是 `route_main.py` 的 `STAGES`（`(段名, 函数, 本段要量的东西)`）；`main()` 按序执行，非 `--auto` 时每段后停下等回车。

### 2.1 ① `s1_out` —— 出启动区（右移）

- 做什么 / 动哪些轴：`car.right(RIGHT_OUT)`，**只动底盘**。
- 坑（交互动线）：非 `--auto` 时先 `car.pause("初始化完成 —— …按回车再右移出启动区")`，免得一启动车就自己走；`--auto` 下这一等由 `main()` 在开跑前**只补一次**（`car.pause(..., auto=False)`），`s1_out` 用 `if not getattr(car, "auto", False)` 判掉 → 两种模式都**只等一次**。现场反馈的"右移之后长时间停止"很可能就是这里在**等回车**。

### 2.2 ② `s2_scan` —— 前进到扫码位 + base 转 180° 扫码 + 转回

- 做什么 / 动哪些轴：底盘（前进）+ base（axis 4）；机械臂、龙门、夹爪不参与。顺序：① `car.base_cw(BASE_180, TTL_VEL, tag="扫码朝向", wait=False)` —— **只发命令、立刻返回**（返回估算耗时）；② `car.fwd(TO_SCAN)` 阻塞等底盘到位；③ 按"谁慢等谁"补足 base 剩余时间（底盘通常更慢，多数时候不用补）；④ `scan_from_monitor()` 向推流页面 `/state` 读侧装相机解码结果（**连续 3 帧一致**才采纳）→ `car.show_qr(code)`，超时用 `SC.CODE_DEFAULT`；⑤ `finally` 里 `car.base_ccw(BASE_180, TTL_VEL)` 转回（成功/超时/Ctrl-C 都转回）。
- 坑：**"只发不等"和前进并行**，靠的是固件 0x10/0x11/0x12 本身非阻塞（见 `route_car.base_turn(wait=False)`），省掉 base 一整段（≈1.4s）。**扫完必须转回**：侧装扫码相机在龙门架右侧，只有 base 转半圈才照得到二维码，不转回后面进原料区的 90° 作业姿态就是歪的；转 180° 时龙门 + 机械臂会扫过整片空间，先清场。`BASE_180` 理论 = 2×`BASE_90`，但机械回差会累积，现场单独量一次更准。

### 2.3 ③ `s3_material` —— 进原料区 + base 左转 + 按取料顺序走位取料

- 做什么 / 动哪些轴：`car.fwd(TO_MATERIAL)` → `car.cur_cm = 0.0` → `car.base_left(BASE_90, TTL_VEL)` → 按 `pick` 顺序循环 `goto_cm(MATERIAL_CM[mid])` → 瞄准 → 取料 → 放到对应物架；底盘、base、龙门、伸缩、夹爪全动。
- `PICK_IN_ROUTE = False` 退回"只走位"（每个号位 `car.pause()` 等确认），供单独标定跑图。工序细节见 §3。
- 坑：★本段跑完**就地停下、不回 1 号位**，出区补偿交给 ④。

### 2.4 ④ `s4_leave_material` —— 出原料区（前进）

- 做什么 / 动哪些轴：`fwd = TO_PROCESS - car.cur_cm`，正数 `car.fwd(fwd)`、负数 `car.back(-fwd)`；只动底盘。
- 坑：原料区不再绕回 1 号位，**用"少走 `cur_cm`"把绝对位置补回来** —— 出区后的绝对位置与老流程（先退回 1 号位再前进 `TO_PROCESS`）完全一致，⑤⑥⑦ 段里程一个都不用改。例：3 号位（24cm）老流程退到 0 再前进 82cm，现在直接从 24cm 前进 58cm。读不到 `cur_cm` 时 `getattr(car, "cur_cm", 0.0)` 兜底成 0 → 退回原行为（不会少走、也不会撞）。

### 2.5 ⑤ `s5_spin` —— 原地自旋（顺时针）

- 做什么 / 动哪些轴：`car.spin(SPIN_DEG)`（`RouteCar.spin(deg, ccw=False)` 默认顺时针），只动底盘；无机械动作、无补偿逻辑。

### 2.6 ⑥ `s6_process` —— 进加工区 + base 左转 + 按放置顺序放置

- 做什么 / 动哪些轴：`car.fwd(ENTER_PROCESS)` → `car.cur_cm = 0.0` → 解析 `place` → `SC.place_plan(place)` → 逐个靶位 `goto_cm(TARGET_CM[tgt])` → `place_demo.run_one(...)`；全套轴都动。

## 3. 取料工序（原料区，`s3_material` + `grab_demo.py`）

### 3.1 工序顺序

```
（进区时一次）base 左转 90° 到作业位
  └─ 每个号位： goto_cm 走位 → 瞄准 → 取料(PICK_STEPS) → [归零并入] 放到物架(RACK_STEPS)
```

- **瞄准**：`aim_and_track(car, _ColorArg(color), _base_deg, tag="M%d")` —— 内部 `car.aim(mode="color", …)`，并把瞄准挪走的 base 脉冲记进软跟踪、把 offset 返回给调用方（见 `grab_demo.aim_and_track()`）。
- **取料**：`car.pick_here(expect_color=color, steps=PICK_STEPS, blind=True, aim=False)`；`aim=False` 是因为瞄准已在上一句单独做过（重瞄一次既慢、又拿不到 offset）。
- **归零**：★跑图里**不单独串行做**，由 `merge_zero_into_steps()` 并进放物架动作组**第①步**（见 §3.3）。逻辑位置在"瞄准之后、放物架之前"；夹料本身不受影响，因为 `PICK_STEPS` 里**没有伸缩步骤**（地面取料只下龙门 + 开合夹爪，见 `grab_demo.PICK_STEPS` 与 `car.DEFAULT_PICK_STEPS` 注释）。
- **放物架**：`_run_rack(car, _r_steps, rack, _base_deg, prefix=…)` → `(新 base 角度, 成功步数, 总步数)`。
- `grab_demo.py` 单机调试的等价顺序是 `h`（归位）→ `l`（进作业位）→ `a`（瞄准）→ `g`（取料）→ `1/2/3`（放物架，里面**先 `rack_zero()` 串行归零**再 `_run_rack`）；跑图把这两步合并了。

### 3.2 物架归置规则

```python
RACK_OF_COLOR = {"red": 1, "green": 2, "blue": 3}     # route_main.py 参数区，不在 school_config.py
```

与 `school_config.COLOR_OF`（`1=red/2=green/3=blue`）一致，所以"颜色对应的物架号"恰好等于物料编号本身；仍按**颜色→物架**显式写出，以后改规则只动这一行。`RACK_STEPS` 也按物架号索引（`RACK_STEPS[rack]`，`rack ∈ {1,2,3}`）。⚠️ 找"物架规则"别只翻 `school_config.py` —— 它在 `route_main.py` 里。

### 3.3 `merge_zero_into_steps()`：为什么把"归零"并进第①步

原实现 `rack_zero()` 是**串行**的：先把 base 还回去等一段、再把伸缩还回去等一段，然后动作组才开始抬龙门（又等一段）。这三件事落在**三个不同的轴**上、互不干涉，而固件 0x10/0x11/0x12 本来就**非阻塞** → 可以同时做。该函数把 `steps[0]`（通常 `lift_up`）与两个反向 `axis` 子步合成 `("par", [...])`：

```python
["par", [ steps[0],                                        # ① 抬龙门（axis 2）
          ["axis", 4, 1 if ob > 0 else 0, abs(ob), bv],    # base 回正（ob = 瞄准的 base 偏移）
          ["axis", 1, 1 if oa > 0 else 0, abs(oa), av] ]]  # 伸缩回正（oa = 瞄准的 arm 偏移）
```

- base 回正脉冲 = **瞄准偏移的相反数** → 精确回到"瞄准之前"，因此**不需要**再补一次 `goto_base_deg()`。
- `aim_off` 为空 / 没偏移 / `steps` 为空时原样返回（不改入参）。
- ⚠️ base 软跟踪的记账由 `_run_rack` 自动完成（见下），调用方**不要**再补记一次，否则记两遍。

### 3.4 `_run_rack()` 与 `_track_par_base()`：为什么要自动补记 base 软跟踪

`_run_rack()` 除照单执行外还做两件事：① **把 base 那两步改成绝对角定位** —— 动作组里 `("base_right", 脉冲)` 是**相对**转动、隐含"此刻 base 正好在 90°"，现场在 0°（初始化位置）直接点 1 号位就会转到反方向（2026-09-17"点 1 却向右转"）；执行时改走 `goto_base_deg(car, base_deg, tgt)`，`tgt = RACK_WORK_DEG - RACK_TURN_DEG[n]`，动作组里的脉冲值只作为"从 90° 出发该转多少"的记录供 `p` 打印/抄写。② **脉冲自检** —— 某步脉冲 ≤ 0 时只**跳过该步**并告警、后面照跑（`pack_ttl` 会抛 `PackError` 打断整组，症状是"放完料之后没有后续动作"）；`par` / `wait` / `parallel` / `both` 排除在自检外，否则 `int([...])` 抛异常会被误判成"脉冲非法"并跳过整步。

`_track_par_base(step, base_deg)`：并行组里若有 base 动作，**立刻**把那笔脉冲换算成角度记进软跟踪。**为什么必须做**：base 没有编码器反馈，"现在多少度"完全靠软跟踪；第①步是并行组（含 base 回正），第②步就是 `("base_right", …)` 且会按"当前 `base_deg`"算绝对角差值 —— 不记账就会用**旧角度**去算，多转/少转一个归零量。

## 4. 放置工序（加工区，`s6_process` + `place_demo.run_one()`）

### 4.1 完整顺序

```
① 回 90° 作业位   goto_base_deg(RACK_WORK_DEG)
② 瞄准靶位        do_aim_target()  →  ring 模式找圆环中心，返回 off
③ 归零            ★并进 ④ 的第①步三轴并行（不单独串行做）
④ 去物架夹料      do_pick_from_rack(rack, aim_off=_home_off) → PICK_FROM_RACK_STEPS
⑤ 回放到靶心      do_replay_aim(off)   →  car.replay(off, sign=+1)
⑥ 放置            do_place()  →  PLACE_STEPS（下放 → 松爪 → 抬回）
⑦ 回零            do_place_zero(off)   →  car.replay(off, sign=-1)
```

返回 `(执行后的 base 角度, 本轮用到的瞄准偏移 off)`；`s6_process` 把 `_base_deg` 串起来传给下一个靶位。

### 4.2 为什么顺序是这样（★本版重点）

瞄准一定会微调 base 和**伸缩**（`off` 常有几百脉冲）。要让"瞄准算出的偏移"真正被**用上**，必须走"瞄 → 归零 → 夹料 → 回放"：① `off` 是后面**归零与回放的唯一依据**，所以必须先瞄；② `car.replay(off, sign=-1)` 回到"瞄准之前" = **夹料的确定起点**；③ 夹料动作组首尾净位移为 0（`arm_in` 与 `arm_out` 等量抵消、base 是绝对角定位必回 90°、龙门净高度 0），所以夹完料的状态与"归零后"一致；④ 再 `car.replay(off, sign=+1)` 就**精确回到刚瞄好的靶心**，然后放置。

原实现是"先夹料、再瞄准"：夹料用不着那个 `off`，等瞄完再放，**瞄准结果完全没用上**（`off` 只在日志里出现）—— 这是踩过的坑。现场验证过的 `aim.py` 的 `place_mission()` 是同一套结构：`converge → replay(off,-1) → BUILTIN_GRAB_VEH → replay(off,+1) → BUILTIN_PLACE`，对应本 demo 的按键顺序 `a → z → P → b → 0`。

### 4.3 为什么必须归零（放料前一次、放料后又一次）

- **放料前的归零**：瞄准会用**伸缩**修画面 y（`offset_arm` 常有几百脉冲），而动作组里 `("arm_in", RACK_ARM_IN)` 是**相对**位移 —— 不归零时缩回落点变成"原位 + 瞄准偏移 − `RACK_ARM_IN`"，**每次都不一样**，重复性差、可能撞物架。base 是绝对角定位、龙门瞄准时不动，本已干净，一并还回去更省事。
- **放料后的回零**（车主 2026-09-18："每次在加工区标靶上放完物料也要进行回零"）：放料结束时 base / 伸缩还停在**靶心对齐**的位置；下一个靶位开头虽然会 `goto_base_deg(90°)` 把 **base** 拉回来，但**伸缩是相对位移、没人纠正** → 每个靶位的伸缩起点都不同（多放几个靶位后可能撞物架）。做法同归零：`car.replay(off, sign=-1)`；`do_place_zero()` 只是把 `rack_zero()` 包一层、日志写成"放完料回零"。
- 只瞄不放（`aim=True, pick=False`）时**不归零也不回放**，只做放料后的回零 —— 靶位就是靠瞄准对出来的，放料必须落在瞄准后的那个位置上（见 `run_one()` 注释）。
- ⚠️ 跑图里 ③ 是"并进 ④ 第①步"的，不单独调用 `rack_zero()`；而 `place_demo` 手动按 `z` 时走的是串行的 `rack_zero()`（两条路径动作等价，只是等待时间不同）。

### 4.4 加工区用 ring 模式，不是 color

`do_aim_target()` 传 `mode="ring"`：加工区标靶是**同心虚线圆环**（中间是空的），走 `ring_center_detect_v2.RingDetector`（`close_k=9` 闭运算把虚线环连成实心环带再取最小外接圆心，`center_gate_r` 只认画面中心附近的环）。用 color 模式（找实心色块质心）时填充率/圆度判据过不了 → 每帧都检测不到 → `BlobTracker` 的 stale 保持把**上一轮旧中心**当 `found=True` 返回 → 上层算出"已经在中心附近" → **三拍零修正的"假收敛"**（现场证据：三个靶位 offset 全是 `{'base': 0, 'arm': 0}`，一个动作都没发）。`TARGET_COLOR` 仍保留，只用于日志与颜色一致性检查。

## 5. `PLACEMENT_MAP` 规则

```python
# school_config.py
PLACEMENT_MAP = {"1": 1, "2": 2, "3": 3}      # ★2026-09-19 车主定：同色对齐
```

| 版本 | 映射 | 含义 |
|---|---|---|
| **当前（2026-09-19 起）** | `{"1":1,"2":2,"3":3}` | 同色对齐：1 号料（红）→1 号靶（红）、2 绿→2 绿、3 蓝→3 蓝 |
| 更早一轮 | `{"3":1,"2":2,"1":3}` | 交叉：3 号料→1 号靶、1 号料→3 号靶（旧说明见 `校赛开发.md` 第 19 行） |

⚠️ `grab_demo.py` 的 `RACK_TURN_DEG` 注释把号位绝对角写成 `30° / 0° / -30°`，而代码 `{1:55, 2:90, 3:125}` 算出来是 `35° / 0° / -35°`（`place_demo.py` 的注释是对的）。以代码为准，注释过时。

## 6. 动作组数据结构

### 6.1 单步的两种写法与别名表

```python
("axis", 轴号, 方向, 脉冲, 速度)      # 通用形式；速度缺省 = 40（car.step_to_axis）
("lift_up", 脉冲, 速度)              # 别名形式；缺省时用 _STEP_ALIAS 里的默认值
("grip_open",)                       # 舵机即时动作，无参数
("wait", 毫秒)   ("break", "说明")    # 等待 / 断点（断点只在上位机逐条执行时有意义）
# 别名（car.py 的 _STEP_ALIAS，格式：别名 = 轴/方向/默认脉冲/默认速度）
arm_out   = 1 伸缩, FWD 前伸, 3000, 30          lift_up   = 2 龙门, REV 抬升, 2400, 40
arm_in    = 1 伸缩, REV 后缩, 3000, 40          lift_down = 2 龙门, FWD 下放, 2400, 30
base_left = 4 base, FWD 左转/逆时针, 6400, 40   base_right = 4 base, REV 右转/顺时针, 6400, 40
```

其它可识别键：`grip_close`/`close`、`grip_open`/`open`、`grip_angle`/`grip`（带角度）、`wait`、`break`、`par`/`parallel`/`both`。识别不到就打 `!! 未知步骤` 并返回 `None`（见 `apply_step()` / `step_to_axis()`）。

### 6.2 并行形式

```python
("par", [ 子步1, 子步2, … ])          # 子步就是上面那些普通步骤
```

`apply_step()` 遇到 `par` 转 `apply_parallel()`：把组内命令**先全部发出去**，再按**最慢的一步**统一等待（耗时由 `ttl_time()` 估：匀速段 + 加减速 + 该轴裕量 + 固定余量）。舵机步骤（`grip_*`）在组内**立即发出**、不参与等待计算。

### 6.3 `PICK_STEPS`（地面取料，`grab_demo.py`）

```python
PICK_STEPS = [
    ("grip_open",),                               # ① 张爪
    ("lift_down", LIFT_DOWN, LIFT_DOWN_VEL),      # ② 龙门下探到料（4400 / 40）
    ("grip_close",),                              # ③ 夹住
    ("lift_up", LIFT_UP, LIFT_UP_VEL),            # ④ 抬起（4400 / 60）
]
```

★不用伸缩台 —— 瞄准完直接下龙门架、开合夹爪（与 `car.DEFAULT_PICK_STEPS` 注释一致）。

### 6.4 `RACK_STEPS[n]`（放到车上物架，`grab_demo.py`，n = 1/2/3）

参数：`RACK_WORK_DEG = 90.0`、`RACK_TURN_DEG = {1:55, 2:90, 3:125}`、`RACK_LIFT_UP = 2800`、`RACK_ARM_IN = 6500`、`RACK_LIFT_DOWN = 300`、`RACK_LIFT_CLEAR = 300`、`RACK_LIFT_BACK = DOWN − UP − CLEAR = -2800`。n = 1 展开：

```python
[("lift_up",   2800, 60),        # ① 抬龙门，别蹭物架
 ("base_right",2933, 80),        # ② 顺时针转到号位（_deg2pulses(55)）——执行时改绝对角定位
 ("arm_in",    6500, 240),       # ③ 伸缩缩回
 ("lift_down",  300, 40),        # ④ 下放到物架料位
 ("grip_open",),                 # ⑤ 松爪放料
 ("lift_up",    300, 60),        # ⑥ 小抬一段，让夹爪离开物料（转回前抬太高会撞物架）
 ("arm_out",   6500, 240),       # ⑦ ★先把伸缩伸出去（必须！）
 ("base_left", 2933, 80),        # ⑧ 再逆时针转回 90° 工作位
 ("lift_down", 2800, 40)]        # ⑨ 转回之后把龙门送回瞄准开始高度（_back_steps() 按符号判方向）
```

- n = 2 / 3 只有 ②⑧ 步脉冲不同（`_deg2pulses(90)=4800`、`_deg2pulses(125)=6667`），其余步骤三个号位**共用同一批常量** —— 几何依据：三个置物架在以 base 轴为圆心的**同一个圆**上，半径相同、只差角度。
- ★必须先伸伸缩、再转 base：放料时伸缩缩回，物料正好落在**缩回半径**那圈上；保持缩回去转 base，臂会在和物料同一半径上横扫 → **把物料打飞**（"缩着扫掠半径更小更安全"的想法是错的）。
- ★高度账必须配平：① +UP、④ −DOWN、⑥ +CLEAR、⑨ +BACK 四者之和 = 0；当前值 `+2800 − 300 + 300 − 2800 = 0` ✓（第 ⑨ 步实际执行"下放 2800"）。⚠️ 代码是 `RACK_LIFT_CLEAR = 300`，注释多处写"车主定稿 300 → 800"并按 800 算高度账（`−3300`）；以代码值为准、两边**必须同步**。
- 第 ⑨ 步允许为负（= 下放）：绝不能把负脉冲直接下发（`pack_ttl` 抛 `PackError` 打断整组），所以由 `_back_steps()` 判符号、取绝对值。

### 6.5 `PICK_FROM_RACK_STEPS[n]`（从车上物架夹料，`place_demo.py`，n = 1/2/3）

## 7. 轴号与方向约定

```python
AXIS_ARM, AXIS_GANTRY, AXIS_BASE = 1, 2, 4     # 伸缩滑台 / 龙门架 / base
FWD, REV = 0, 1                                # 正转 / 反转
BASE_90 = 4800 脉冲 / 90°  →  1° ≈ 53 脉冲（BASE_90/90）
```

| 轴 | 号 / 协议 | 方向约定 |
|---|---|---|
| 伸缩滑台 | 1 / 0x10（TTL id1） | 别名写死：`arm_out` = FWD、`arm_in` = REV；`("axis",1,d,…)` 里 d 同义 |
| 龙门架升降 | 2 / 0x11（TTL id2 + id3 **反向传动**） | 写 2 即可，底层自动带 id3 反向；`lift_up` = REV、`lift_down` = FWD |
| base 轴 | 4 / 0x12（TTL id4） | **FWD = 左转 / 逆时针**，REV = 右转 / 顺时针（`base_left` → FWD） |
| 夹爪 | 舵机 0x14 / 0x15 | 不是 TTL 轴，不进 `apply_parallel` 的等待计算 |

- 本车**没有**独立步进升降轴、**没有**载物台旋转电机 —— 固件 `claw.c` 的 `Lift_GoTo` / `Tray_Turn120` / `Claw_*` 在这台车上是**死代码，别调用**（见 `car.py` 顶部注释）。
- 所有角度↔脉冲换算都走 `BASE_90/90` 这个关系：`_deg2pulses()`、`goto_base_deg()`、软跟踪记账、`BASE_180` 的理论值。
- base **绝对角**定义：初始化结束时 base 在正前方 = **0°**，**左转为正**（+90° = 左侧作业位）；`RACK_WORK_DEG = 90.0`，号位绝对角 = `RACK_WORK_DEG − RACK_TURN_DEG[n]`。
- ⚠️ base **没有角度反馈**（TTL 闭环电机有编码器，但固件没回传上位机）→ 全靠上位机软跟踪；手动拧过 base 后软跟踪会失准，按一次 `l`（grab_demo / place_demo 都有）按"目标 90°"重新对齐。

## 8. 里程软跟踪的约定（★最容易算错的一处）

```python
# car.py
self.cur_cm = 0.0                      # 当前纵向坐标（进区作业起点 = 0）
def goto_cm(self, target_cm, tag=""):
    d = float(target_cm) - self.cur_cm
    …
    self.cur_cm = float(target_cm)     # ← 唯一写 cur_cm 的地方
```

| 规则 | 说明 | 出处 |
|---|---|---|
| `cur_cm` **只由 `goto_cm()` 记账** | `fwd()` / `back()` / `left()` / `right()` / `spin()` **都不更新** | `car.py` 的 `goto_cm()` |
| 进区时手工清零 | ③⑥ 段都在 `car.fwd(TO_…)` 之后写 `car.cur_cm = 0.0`，把"进区作业起点"定义为 0（正对 1 号位） | `route_main.py` |
| 区内走位用 `goto_cm()` | 它会记账，所以"3 号位 24cm → 1 号位 0cm"能算出该后退 24cm | `s3_material` / `s6_process` |
| 出区用 `fwd = TO_XXX - cur_cm` 补偿 | 不绕回 1 号位，只补差额，保证**出区后的绝对位置与老流程一致** | `s4_leave_material` / `s7_finish` |
| 读不到时兜底 0 | `float(getattr(car, "cur_cm", 0.0) or 0.0)` → 退回"前进整段"的老行为 | 同上 |

要点：`cur_cm` 是**软跟踪**、不是传感器读数 —— 底盘丢步/打滑不会纠正，它只保证"别少走/别多走"，不保证"走得准"；要走准得靠 `route_debug.py` 标定里程参数。

## 9. 并行组的限制

- **同一轴不能在同一 `par` 组里出现两次**：TTL 位置命令是**覆盖式**的，后发的会覆盖前面的目标位置。`apply_parallel()` 会检测并打告警：`!! 同一个轴在并行组里出现了两次（… → …），后面的会覆盖前面的目标！请拆成两个 par 组` —— 不静默出错，但结果一定不是想要的。
- **能并行是因为固件本身非阻塞**：0x10/0x11/0x12"发完即返回,不等待"（`TTLctrl.c`），所以 `fire_axis()` 只是"只发不等"，再按 `ttl_time()` 估的最长一步统一 `sleep`（见 `apply_parallel()`）。
- 因此并行组的正确用法是**跨轴**：`merge_zero_into_steps()` 造的组是 龙门(2) + base(4) + 伸缩(1)，三轴互不干涉。同一轴要串两段就拆成两个 `par` 组或老实串行（`PICK_FROM_RACK_STEPS` 的 ④⑤ 两段 `lift_down` 就是串着写的）。
- 等待时间是**估**的（匀速 + 加减速 + 轴裕量 + 固定余量；参数在 `school_config.py` 的 `TTL_ACC_RPM_PER_S` / `TTL_TIME_EXTRA_S` / `TTL_EXTRA_S`）。估短了会出现"伸缩台还在飞，龙门下放 + 关爪的命令已经发出去了" —— 这类症状先调这三个参数，不是改动作组顺序。

## 10. 调试手段

### 10.1 `route_main.py` 的运行选项

- 默认（只给 `--port /dev/stm32`）：**分段跑** —— 每段后打 `⏸ 【本段完成 —— 等你按回车才走下一段】要量的东西：…` 并等回车，输入 `q` 退出。
- `--auto` 一口气跑完、不在每段后停（开跑前仍保留**一次**回车确认）；`--start N` 从第 N 段开始（1~7），用于只复跑某一段；`--dry-run` 不连车、不动电机（验证流程与分段交互）；`--no-monitor` 不开双摄推流。
- `--no-init` ★跳过上电初始化动作组 —— **臂已在起始位时必须用它**，否则会继续往同方向走顶死限位；`--init` 强制初始化；`--monitor-port` / `--scan-cam` 指定推流端口与侧装相机编号。

### 10.2 `route_debug.py`（走位标定助手）

它不替人决定参数，只做"**发一段 → 量实际值 → 算比例并给出该填多少**"（`suggest()`：`需要的值 = 当前值 × 目标 / 实测`）。菜单：`m` 里程标定（`MILESTONES` 里 7 段，或自定义）｜`s` 自旋标定（发 `SPIN_DEG` → 输入实测角度）｜`b` base 标定（发 `BASE_90` 脉冲 → 输入臂实际转了多少度）｜`g` 手动发一段｜`p` 显示当前参数｜`h` 急停。★`FINISH_RIGHT` 在标定清单里，但 `s7_finish` 末尾硬编码的 `right(31)` / `fwd(17)` **不在**。

### 10.3 `car.pause()`（分段交互的统一入口）

`car.pause(msg, auto=None)`：`auto=False`（或 `self.auto=False`）时打印提示并等回车；输入 `q` 或 stdin 结束 → 抛 `KeyboardInterrupt`（主程序停车并干净退出）；`auto=True` 时直接返回。`--auto` 通过 `car.auto` 让所有 `pause()` 自动跳过，**只有开跑前那一次**用 `auto=False` 强制等。

### 10.4 两个 demo 的交互命令

`grab_demo.py`（原料区：瞄准物料 → 夹取 → 放到物架）：`h`/`l` 归位(→0°) / 进左侧作业位(→90°，绝对角定位)｜`a` 只瞄准（并记住 offset）｜`g` 取料一遍（瞄准 + `PICK_STEPS`）｜`1`/`2`/`3` 放到物架号位（先 `rack_zero()` 串行归零，再 `_run_rack`；可加参数覆盖转角度）｜`A`/`B`/`C` 一条龙｜`n` 切换动作组｜`s` 单步跑（回车=执行 `s`=跳过 `r`=重跑上一步 `q`=退出）｜`p` 打印动作组（可直接粘回参数区）｜`e N [脉冲] [速度]` 改第 N 步 / `i N 名称 …` 插入 / `d N` 删除｜`m` 手动发单个动作（base/lift/arm/grip/wait）｜`v [帧数]` 静置抖动测试（**不动电机**，先分清"视觉噪声"还是"控制/机械"）｜`c [base脉冲] [arm脉冲]` 重测 K / 查耦合 / 验方向（推荐 `c 200 800`，会动电机）｜`k` / `k 名字 值` 查看与现场改瞄准参数｜`x` 停车。

## § 改动流程时的注意事项

**改完必须验的**

1. `python3 -u route_main.py --dry-run` 先验流程骨架（分段、任务码解析、动作组拼装、`par` 组、脉冲自检），再 `--dry-run --auto` 验一口气模式；两个 demo 也各跑一次 `--dry-run`（不动电机就能把动作组结构、菜单、`par` 组、脉冲自检全跑一遍）。
2. 改**任何动作脉冲/角度**后，用 demo 的 `p` 打印真实动作组、`s` 单步验，再抄回参数区（别直接改代码数字就上整场）；改**里程 / 自旋 / `BASE_90`** 后必须用 `route_debug.py` 重标（`m` / `s` / `b`）并核对建议值。
3. 实跑建议 `--start N` 只复跑受影响的那一段，别整场重跑。

**参数联动清单（改一个要想到另一个）**

| 改了 | 必须同时检查 |
|---|---|
| `BASE_90` | `BASE_180`（理论 2×，实际单独量）、`_deg2pulses()`、`goto_base_deg()`、软跟踪换算、`setup(base90=…)` 下发的 `base_left90_pulses/base_right90_pulses`、`route_debug` 的 `b` 标定 |
| `PITCH` | `MATERIAL_CM` / `TARGET_CM`（都由 `PITCH` 生成）；核对 `route_main` 里"间隔 10cm"的注释 |
| `RACK_LIFT_UP / DOWN / CLEAR` | `RACK_LIFT_BACK = DOWN − UP − CLEAR` 必须**四者配平为 0**；`grab_demo` 与 `place_demo` **两份常量手工同步** |
| `RACK_TURN_DEG` | 两个 demo 各一份、必须同步；`_deg2pulses()` 值是"从 90° 出发"的记录值，执行走绝对角 |
| `PLACEMENT_MAP` | `place_demo.TARGET_COLOR`（同色对齐时天然一致）、`s6_process` 的颜色一致性告警、`RACK_OF_COLOR`（取料来源按颜色算，一般不用动） |
| `TO_PROCESS` / `TO_FINISH` | ④⑦ 是**补偿式**写法（`TO_XXX − cur_cm`）；别改回"固定前进量"，否则 3 号位会多走一截 |
| `RIGHT_OUT` / `TO_SCAN` / `TO_MATERIAL` / `ENTER_PROCESS` / `SPIN_DEG` / `FINISH_RIGHT` | 都在 `route_debug.MILESTONES` 里可标定；`s7_finish` 的 `right(31)` / `fwd(17)` 不在，要手改 |
| `GRIP_OPEN_ANGLE` / `GRIP_CLOSE_ANGLE` | 三个程序要一致；**改完必须重启程序**（`setup()` 只在启动时下发一次）；角度越小爪片张得越开 |
| `CAM_EXPOSURE` / `CAM_ROTATE` | 改曝光要重测瞄准（过曝让质心飘）；`CAM_ROTATE` **必须显式 `none`**，否则 x/y 对调、瞄准必废 |
| `TTL_VEL` / `AIM_VEL_*` | `TTL_VEL` 被各 demo/动作组引用（base 大转），**不影响瞄准**（瞄准走 `AIM_VEL_BASE/ARM`） |

**容易踩的三个坑（都是现场发生过的）**

1. **`sys.path` 顺序**：共享模块会把老工程 `/root/VisualBot` 也塞进 `sys.path`，那里有同名的旧版 `aim.py / car.py / vision.py` —— 顺序插错就会命中旧版，三阶段瞄准/软化/arm 阻尼/实测 K **全部静默失效**；三个入口文件都用"倒序插入 + 先清掉重插"解决，别简化回 `insert(0, …)` 循环。
2. **注释与代码打架**：已标出多处（`PITCH` vs "10cm"、`RACK_LIFT_CLEAR` 300 vs "定稿 800"、`PICK_FROM_RACK_STEPS` 9 步 vs 11 步、`RACK_TURN_DEG` 30° vs 35°）。**一律以代码为准**，改参数时顺手把注释改对，否则下一个人会按注释算错高度账。
3. **归零/回放不要重复做**：`merge_zero_into_steps()` 之后由 `_run_rack()` 自动记账 base，调用方再补记一次就记两遍；`place_demo` 的 `z` / `b` 用 `aim_state` 状态机防止重复按，写新流程时要保留类似保护。

**还没定 / 待确认的项（不要当成结论用）**

- ⚠️ 相邻号位间距到底是 10cm 还是 `PITCH = 12`（注释与代码冲突）。
- ⚠️ `RACK_LIFT_CLEAR` 该是 300 还是 800（注释说车主定稿 800，代码是 300）。
- ⚠️ `PLACE_DOWN = PLACE_UP = 4000`（靶面下放量）注释仍写"现场用 `m` 手试、`e` 改"。
- ⚠️ 物料是否**只有固定位置**：`school_config.POS_OF` 标着 `[待确认]`；当前跑图直接用"物料编号 = 号位号"（`MATERIAL_CM[int(mid)]`），没有走 `POS_OF`。
