# 现场调参轨迹与「部署覆盖」事故档案（2026-09-16）

> 这份文件回答一个问题：**板子上刚调好的参数，被部署脚本冲掉之后，怎么找回来。**
> 结论先写：这次靠 **RDK 上 VSCode 服务端的本地历史**（`~/.vscode-server/data/User/History/`）找回来了。
> 所有现场版本的源码快照已存档在 `校赛/_field_snapshots/`，别再丢。

---

## 1. 事故经过（时间线）

| 时刻 | 事件 |
|---|---|
| 09-16 16:02 | 我部署上位机到 `rdk:/root/VisualBot_20260916_1602`（`VisualBot_current` 软链指向它） |
| 22:15–22:37 | **车主在 RDK 上用 VSCode Remote-SSH 直接改 `校赛/school_main.py` 的现场参数区**（每改一次保存一次，共 7 次） |
| 22:40 | 我又跑了一次部署 → **`scp` 无条件覆盖** `school_main.py`，现场参数全没了 |
| 22:47 | 改用「从历史恢复」：拉回 VSCode 服务端本地历史里的 7 个快照，比对出车主的改动并复原 |

**根因**：部署脚本只做单向 `scp`，且**现场调参是在板子上做的**（Windows 侧没有这些改动）→ 一部署就回退。
**次生问题**：`school_main.py` 没有 `.bak`，`__pycache__` 里的 `.pyc` 也被同一次运行刷掉了。

## 2. 恢复过程（可复现）

```powershell
# ① 在 RDK 上看有哪些"被编辑过的文件"的本地历史
ssh -n rdk 'ls -la /root/.vscode-server/data/User/History/'
# 每个子目录一个 entries.json，里面 resource 字段写明对应哪个文件：
ssh -n rdk 'cat /root/.vscode-server/data/User/History/458a14d3/entries.json'
# → resource = vscode-remote://ssh-remote+rdk/root/VisualBot_20260916_1602/校赛/school_main.py

# ② 全部拉回本地比对（7 个快照）
scp -r rdk:/root/.vscode-server/data/User/History/458a14d3 "$env:TEMP\rdkhist\458a14d3"
```

> ⚠️ VSCode 本地历史保存的是**每次保存「之前」的内容**，所以条目 `VH57`（22:37:44）=
> 22:37:44 那次保存**前**的磁盘内容。**22:37:44 之后又保存的那一版，历史里不存在**（已被部署覆盖）。
> 因此恢复出来的是「倒数第二版」，与车主最终版可能还差一两次微调 —— 需要车主过一眼参数值确认。

**辅助手段（`.pyc` 反查）**：`__pycache__/*.pyc` 的头部 12 字节存着编译时源文件的 mtime/size，
且模块级常量可以直接反汇编出来，用来判断"某个 .pyc 到底编译自哪一版"。脚本见 `_tools/dump_pyc.py`（本机临时脚本），
这次就是靠它确认「远端当前的 `school_main.py` 是我部署的那版（`CHASSIS_VEL=8 / BASE_90=6400 / RIGHT_OUT=30 …`）」，
从而排除"远端还有现场版"的可能。

读法（车主当时的思路，供下次参考）：
- **先把行程整体砍到 1/3 左右**（`RIGHT_OUT 30→10`、`TO_SCAN 60→20`、`TO_MATERIAL 80→10`、`PITCH 35→5`）——
  说明部署默认值是按"大场地"估的，实测工位间距只有 **5cm**、各个前进段只有 20~50cm；
- **自旋 90°→70°**：`SPIN_DEG` 变小 = 实际转过头了（发 90° 实际多转）；
- **`BASE_90` 6400→4800**：base 轴 90° 的真实脉冲数 ≈ 4800（不是按理论 3200×? 算的那个）；
- **速度最后定在档位 7**（`CHASSIS_VEL`）；
- 之后又在 22:35–22:37 做**小数级微调**（`RIGHT_OUT 15→12`、`TO_SCAN 30→35→33`、`TO_PROCESS 30→50`）——这几次就是"现场一站一站量"的结果。

## 5. 防再犯（已落地，别再绕过）

1. **部署前先取回现场改动**（新脚本，反向部署）：
   ```powershell
   powershell -ExecutionPolicy Bypass -File 整机程序设计\deploy_pi\pull_from_rdk.ps1            # 只看差异
   powershell -ExecutionPolicy Bypass -File 整机程序设计\deploy_pi\pull_from_rdk.ps1 -Apply      # 差异文件拉回本地（先备份）
   powershell -ExecutionPolicy Bypass -File 整机程序设计\deploy_pi\pull_from_rdk.ps1 -WithHistory # 顺便打包 VSCode 历史存档
   ```
2. **部署脚本默认保护现场参数**：`deploy_to_rdk.ps1` 对受保护清单（默认 `school_main.py`，`-Protect` 可加）
   做 **远端 md5 vs 本地 md5** 比较，只要不同就**跳过不覆盖**并打印提示；
   真要覆盖必须显式加 **`-Force`**（此时会先把远端备份成 `school_main.py.field_<时间戳>.bak`）。
   实测：故意在板上加一行注释 → 部署时报"板子上这些文件有【现场改动】"并跳过，远端 md5 不变。
3. **改参优先在 Windows 侧本地改 → 部署**；如果必须在板上改，**改完立刻 pull 回本地**（一条命令的事）。
4. 参数改动记录就写在本文件第 3 节的表里（或直接引用 `_field_snapshots/` 里对应的快照）。
