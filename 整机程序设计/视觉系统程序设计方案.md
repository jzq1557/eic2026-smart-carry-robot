# 智能搬运赛项视觉系统程序设计方案

**适用平台**：树莓派 4B + USB 摄像头（OpenCV / Python）
**依据文档**：附件2-1《命题与运行》、附件2-2《评分与规则》（2026 上海工创赛 / 2027 国赛·智能+工程创新赛道）

---

## 1. 赛题视觉需求提取

### 1.1 视觉强相关任务与计分点（评分规则 doc2）

| # | 视觉任务 | 得分/判罚 | 视觉输出 |
|---|---------|----------|---------|
| 1 | 读取二维码任务码并在显示装置显示 | **1 分** | 任务码字符串（4 组三位数） |
| 2 | 按任务码顺序正确抓取物料（抓取并放到机器人上） | **每件 2 分** | 目标颜色物料的实时位置 |
| 3 | 粗加工区/暂存区按圆环精度放置 | **1环15 / 2环10 / 3环7 / 4环5 / 5环3 / 6环1 分**（非线性的核心分） | 环心坐标、对位偏差 Δx/Δy |
| 4 | 暂存区第二批码垛（颜色一致 + 对齐不倾倒） | 分数同第一批 | 下层物料顶面颜色、上下层轮廓偏差 |
| 5 | 回到启停区 | **2 分** | 蓝色启停区检测 |
| 6 | 正确显示抓取/放置统计 | **各 2 分** | 抓取成功/放置成功/环级事件流 |
| 7 | 只在灰色车道行驶，不得进入其他颜色区域 | **越界本轮结束** | 车道中线偏差、区域颜色报警 |
| 8 | 避开黑色障碍柱（φ50×100mm，位置随机） | 不直接得分，撞上影响时间 | 障碍方位与距离 |
| 9 | 圆环中间数字校验（1/2/3 号位） | 辅助放置正确性 | 数字识别结果 |
| 10 | 物料未上机不得驶往下一区域 | 违规不计成绩 | "载物区已检测到物料"确认 |

> 计分结构：B = 100 × 本队得分 / 参赛队最高得分。放置精度（15 分档）是视觉能贡献最大的分差点，**优先级应排在"抓得准"之上**。
> 理论满分参考：1 + 2×6 + 15×6 + 2 + 2 + 2 = 109 分（未归一化）。

### 1.2 场地与物料参数（命题 doc1，直接影响算法参数）

| 项目 | 参数 |
|------|------|
| 场地 | 2400×2400mm，中间十字灰色车道宽 400mm |
| 淡黄色区 | 4 个，450×450mm（禁入） |
| 启停区 | 蓝色，300×300mm，2 处（抽签定出发位） |
| 障碍物 | 黑色圆柱 φ50×100mm，位置随机 |
| 原料区/成品区 | 顶面 φ300mm 圆形电动转盘，高 80–100mm，**匀速 6–10s/圈，每转有停留**，3 个物料 120° 均布 |
| 暂存/粗加工/精加工区 | 580×150mm，同心圆环 φ1~φ6，环线宽 1.5mm，环心标数字 |
| 圆环外径 | φ1=φ+3、φ2=φ1+5、φ3=φ2+7、φ4=φ3+10、φ5=φ4+10、φ6=φ5+10（φ 为物料最大直径） |
| 物料 | 3D 打印 ABS/PLA，≤80mm、≤100g；**红/黄/蓝/绿/黑/浅蓝**（浅蓝为 PLA），现场可能有色差 |
| 任务码 | 四组三位数以 "+" 连接，如 `156+123+516+231`；颜色编号：红1 黄2 蓝3 绿4 黑5 浅蓝6 |
| 二维码板 | A4 横放、竖直安装于赛场内侧，QR 码 80×80mm（含边框）居中，位置随机 |

### 1.3 与视觉相关的关键规则约束

1. **仅允许垂直向下补光，不允许对场地遮挡** → 前视相机只能靠现场环境光 + 自身曝光控制；下视可用环形灯。
2. **15 秒静止判负**（等转盘可额外加 8 秒）→ 视觉"等转盘"期间必须告知主控做小幅度蠕动。
3. **一键启动，运行中不得触碰机器人和笔记本，禁止遥控** → 与笔记本的通信只能用于单向遥测。
4. **不允许手爪夹持物料运送** → 抓取后必须放到载物平台，视觉需确认"物料在平台、手爪已释放"。
5. 机器人投影 ≤300×300mm、高 ≤400mm → 相机安装空间受限。
6. 转盘转向随机、停止位置有误差、停留次数与时长现场定 → 抓取策略必须同时支持"停转抓取"与"转动中跟踪"。

## 2. 视觉任务与技术映射总表

| 视觉任务 | 关键技术 | 输出接口（给主控） |
|---------|---------|------------------|
| 读二维码 | OpenCV QRCodeDetector + pyzbar 双引擎、多尺度、多帧表决、格式校验 | 任务码字符串 + 解析后的 4×3 数组 |
| 颜色识别 | HSV 模型 + 现场自动标定 + 直方图/距离分类 + 时序投票 | 颜色编号（1~6）+ 置信度 |
| 转盘物料定位 | 背景减除（MOG2）/帧差 + 颜色掩码 + 极坐标变换 | 物料相对转盘中心的极角/半径 |
| 圆环对位 | HoughCircles/椭圆拟合 + 手眼标定 + 闭环逼近 | 环心像素 → 机器人坐标偏差 Δx/Δy（mm） |
| 码垛检测 | 下视俯拍 + 上下层轮廓对比 | 对齐偏差、颜色一致性 |
| 车道循迹 | HSV 灰色分割 + 连通域质心/边界拟合 | 横向偏差（归一化）+ 航向角 |
| 障碍检测 | 车道 ROI 内黑色连通域 + 尺寸过滤 + 单目测距 | 最近障碍的距离/方位 |
| 区域识别 | 蓝/黄/白/灰颜色分类 | 当前区域类型 + 越界预警 |
| 数字识别 | 模板匹配（1/2/3 字体固定） | 环位编号校验 |
| 统计事件 | 状态机事件流 | 抓取成功/放置成功/环级 |

## 3. 硬件方案

### 3.1 相机选型（建议参数）

| 参数 | 推荐值 | 理由 |
|------|--------|------|
| 接口/输出 | UVC USB，**MJPEG** 优先 | 树莓派 4B USB 总线共享 480Mbps，MJPEG 解码开销远小于带宽开销 |
| 分辨率 | 640×480 常态，1080p 仅二维码近读时用 | 处理速度与精度折中 |
| 镜头 | 前视 70°~90° FOV；下视 90°~120° FOV | 前视远距离读码需要一定放大率；下视广角覆盖 580×150 区域 |
| 快门 | 有条件选全局快门 | 行驶中拍摄避免卷帘倾斜导致车道/圆环变形 |
| 可控性 | 必须支持手动曝光、白平衡锁定（UVC 标准属性） | 颜色识别的前提，见 §5.1 |
| 型号参考 | 免驱 UVC 模组（如 OV2710/IMX219 变焦款），100~200 元档即可 | 比赛硬件无品牌限制 |

### 3.2 相机布局（推荐双相机方案）

```
            ┌──────────────┐
            │  任务码显示屏 │  (≥12mm字高, 顶部醒目位置 — 主控负责)
            └──────┬───────┘
  前视相机(俯仰可微调)──┤  机械臂/抓取机构
  ▼ 看：二维码板/车道/障碍/区域        │
                                     ▼ 下视相机 + LED环形灯(垂直向下补光)
  看：转盘物料 / 载物平台 / 圆环对位 / 码垛
```

- **前视相机**：装于机身前部上方，俯角约 20°~30°（能看到前方 200~1500mm 地面与竖直二维码板）。
- **下视相机**：装于机械臂/机身前部垂直向下（或随机械臂末端运动），高度 150~300mm，负责所有"毫米级"任务。
- 备选：单相机 + 小舵机云台（省 USB 带宽，但云台回零精度会直接变成放置误差，**不建议**用于对位）。
- 镜头加装偏振片（可选）：抑制转盘/物料 ABS 高光反光。

### 3.3 补光

- 规则只允许"垂直向下补光"：在下视相机周围装 LED 环形灯（或贴片灯条 + 均光扩散片），**色温固定**（如 5000K 白光），避免混色温导致颜色漂移。
- 前视相机不做任何补光，靠场馆环境光；若现场灯光有频闪，调试时锁定曝光时间避开频闪条带（见 §5.1）。

### 3.4 算力与带宽预算

- 树莓派 4B（4GB 足够）：双 USB 相机 MJPEG 640×480@30fps × 2 无压力。
- 散热：加散热片/风扇，运行中降频会导致视觉延迟抖动（可关闭 CPU 变频：`performance` 调频策略）。
- 与主控连接：**串口（UART）为主**（115200/921600），WiFi 仅用于调试遥测（笔记本收图/日志，只发不收指令）。

## 4. 软件总体架构

### 4.1 进程/线程模型

```
┌────────────────────────── 树莓派 4B（视觉节点）──────────────────────────┐
│ 主线程 VisionService（命令状态机）                                        │
│   ├─ 相机线程 ×2：Cam(front) / Cam(down)，最新帧缓冲（丢旧帧策略）        │
│   ├─ 工作线程池：按当前任务调度（QR读码 / 车道 / 障碍 / 转盘 / 圆环）      │
│   ├─ UartLink 线程：与主控收发帧协议                                      │
│   └─ 遥测线程：WiFi 推图/日志到笔记本（只发不收，合规）                    │
└──────────────────────────────┬──────────────────────────────────────────┘
                               │ UART（帧协议）
                     ┌─────────▼─────────┐
                     │ 主控制器（STM32/ESP32│ 运动控制/机械臂/任务码显示屏
                     │ 或另一块 Linux）    │ 编码器+陀螺仪定位
                     └───────────────────┘
```

**设计原则**：视觉只输出"观测结果"，不做全局定位与路径规划（那是主控的事）；但视觉提供足够频繁的反馈（车道偏差 20Hz+），主控据此闭环。

> 若团队已用 ROS 可直接映射成 ROS 节点/话题；否则**不要引入 ROS**，串口帧协议开发调试更快、比赛更稳。

### 4.2 通信协议（帧格式 + 命令集）

帧格式（小端）：

```
STX(0xA5) | CMD(1B) | SEQ(1B) | LEN(2B) | PAYLOAD | CRC8(1B) | ETX(0x5A)
```

命令集（视觉端接收 → 执行 → 回包，每包带 SEQ 对号）：

| CMD | 名称 | 请求 | 应答 |
|-----|------|------|------|
| 0x01 | PING | - | 版本号 |
| 0x10 | READ_QR | 无 | 任务码字符串 + 解析结果 4×3 |
| 0x11 | LANE | 无 | 横向偏差(-1~1) + 航向角(°) + 置信度 |
| 0x12 | OBSTACLE | 无 | 距离(mm) + 方位(°) + 数量 |
| 0x13 | FIND_MATERIAL | 颜色编号 1~6 | 物料极角(°) + 半径(mm) + 置信度 |
| 0x14 | ALIGN_RING | 环位编号 1~3 | Δx/Δy(mm) + 对齐完成标志 |
| 0x15 | VERIFY_PLACED | 颜色编号 | 是否在位 + 估算环级(1~6) |
| 0x16 | CHECK_REGION | 无 | 区域类型(灰/蓝/黄/白) |
| 0x17 | WAIT_TURNTABLE | 颜色编号 | 转盘停转信号 + 目标物料位置 |
| 0x18 | VERIFY_LOADED | 无 | 载物区物料颜色编号 |
| 0x1F | EVENT | 事件码 | 抓取成功/放置成功/环级/统计信息 |

### 4.3 视觉端状态机

```
IDLE →(READ_QR)→ READ_QR(近距多帧表决)→ 回传任务码
     →(LANE)→ LINE_TRACKING(持续20Hz)
     →(FIND_MATERIAL)→ TURNTABLE_SCAN → 回传极坐标
     →(ALIGN_RING)→ RING_ALIGN(闭环逼近, 10Hz) → 回传 Δ 直到 <2mm
     →(VERIFY_PLACED / VERIFY_LOADED)→ 单帧确认
     →(CHECK_REGION)→ 区域分类
```

一次只服务一个命令（串行化），命令间可被 PING 打断。

### 4.4 配置管理

所有阈值（HSV 范围、ROI 位置、标定参数、转盘圆心像素坐标）集中到 `config.yaml`，调试时热加载。**比赛现场 3 分钟调试就是改这个文件**，程序不重编译。

## 5. 各视觉模块详细设计

### 5.1 图像采集与相机控制（一切颜色任务的前提）

- 打开相机后立即锁定：`CAP_PROP_AUTO_EXPOSURE=0.25(手动)` → 固定曝光时间；`CAP_PROP_AUTO_WB=0` → 固定白平衡温度。
- **为什么必须锁**：自动曝光/自动白平衡会让同一物料在不同背景（转盘、灰车道、白底）下颜色漂移，6 色分类直接失效。
- 采集线程只保留最新帧（`frame, timestamp`），处理跟不上就丢帧——**永远用最新帧决策**，保证延迟有界。
- 帧率目标：车道 20fps、圆环对位 10fps、QR 专项模式不限帧率。

### 5.2 二维码读取（任务源头，只值 1 分但错了全盘皆输）

任务码格式：`^\d{3}\+\d{3}\+\d{3}\+\d{3}$`，颜色码 ∈{1..6}，位置码 ∈{1..3}。

流程：
1. 主控导航到二维码板前方约 **150~250mm**（80mm 码在 640 宽画幅下需 ≥4~6 px/module；或用 1080p 抓帧），停稳。
2. 连续读 30~50 帧，每帧做：
   - 多尺度缩放（0.75 / 1.0 / 1.25）分别检测（应对尺寸误差）；
   - `cv2.QRCodeDetector` 与 pyzbar（如已装）双引擎，任一命中即记录；
   - 自适应阈值预处理后再检测一遍（应对不均匀光照）。
3. **多帧表决**：相同结果出现 ≥3 帧且通过正则校验 → 确认回传；连续 2 秒无有效结果 → 报告失败并让主控微调位姿（左右平移/绕圈）重试。
4. 防误读：解析出 4×3 数组后做合法性校验，非法结果一律丢弃。
5. 注意板面反光：读码时相机轴线略偏 10°~20° 避开镜面反射。

### 5.3 颜色识别（6 色，含"浅蓝 vs 蓝"难点）

分类空间选 **HSV**（H 圆形距离 + S/V 欧氏距离加权）。

**现场自动标定流程**（每次上场必做，30 秒内完成）：
1. 机器人对转盘拍摄，转盘上 3 个初始物料 + 备用物料作样本；
2. 人工框选/自动分割每个颜色 ROI，记录每色 HSV 均值与标准差 → 存入配置；
3. 若某色样本不足（现场未必 6 色齐全），用"物料色卡"（自备 6 色标定块，上场时贴在机器人内部供下视相机自拍标定——不遮挡场地，合规）。

**分类决策**：
- 先粗分割（按标定中心 ±3σ 阈值）→ 形态学开运算去噪 → 连通域过滤（面积/长宽比，剔除场地杂色）；
- 对候选 ROI 做像素级分类：H 环形距离加权 + S/V 距离 → 取众数；
- **多帧时序投票**（连续 5 帧一致才输出）消除单帧误判。

**难点对策**：
| 难点 | 对策 |
|------|------|
| 浅蓝(PLA) vs 蓝(ABS) | H 相近时用 S 区分（浅蓝饱和度和亮度更高），标定时记录两类样本 |
| 黑 vs 阴影 | 黑色 S 极低 + V 极低；阴影 V 中等，加 V 双阈值 |
| 白底/反光 vs 浅色物料 | 偏振片 + 漫反射环形灯 + 曝光锁定 |
| 现场色差 | 标定样本来自现场物料本身，不是提前烧死阈值 |

### 5.4 转盘物料定位与抓取引导

目标：按任务码顺序，在 φ300mm 转盘（80~100mm 高，6~10s/圈，随机转向）上找到指定颜色物料并给出抓取窗口。

流程：
1. **建模背景**：MOG2 背景减除（`cv2.createBackgroundSubtractorMOG2`），转盘转动时物料是前景、盘面是背景；
2. 目标色掩码 ∩ 前景掩码 → 候选物料连通域；
3. 以**转盘圆心（标定得到的图像坐标）**为原点，输出物料极坐标 `(θ, r)` 与像素尺寸；
4. 抓取策略二选一（由主控决定，视觉都支持）：
   - **停转抓取**：检测到候选物料角速度≈0（连续 N 帧位置不变）→ 发"转盘停稳"信号 + 当前物料极角；
   - **动态抓取**：Kalman 预测物料下一帧极角，输出超前角补偿（主控按预测位置下爪）；
5. 抓取后主控发 `VERIFY_LOADED`：下视相机确认载物区出现该色物料 → 才允许驶往下一区域（**规则强制**）。

> 转盘线速度约 300π/8 ≈ 118mm/s，动态抓取对同步要求高；若转盘每转停留时间足够，优先停转抓取。

### 5.5 圆环检测与高精度放置对位（核心得分模块）

以 φ=50mm 物料为例：φ1≈53、φ2≈58、φ3≈65、φ4≈75、φ5≈85、φ6≈95mm。下视相机距地面约 250mm、视场约 200×150mm 时，最外环直径约 95mm ≈ 图像 300px，足够检测。

流程：
1. **粗定位**：前视相机/编码器导航到目标区域，下视相机开始找圆：灰度 → 高斯模糊 → `HoughCircles`（dp=1.2, minDist=40, param1=80, param2=30，**参数按标定配置**）；
2. 从候选圆中筛选半径落在 φ1~φ6 预期范围的圆，用多个同心圆的**圆心均值**作为环心（抗单圆误检），圆心处数字用模板匹配校验环位编号（1/2/3）；
3. **手眼标定转换**：环心像素 → 机器人坐标偏差 `(Δx, Δy)`（标定见 §6.3）；
4. **闭环逼近**：主控按 Δ 移动 → 再拍再算 → 直到 |Δx|、|Δy| ≤ 2mm 或连续 3 次不收敛（此时按最后 Δ 直接放置，宁慢勿错）；放置时机器人必须完全停稳再拍照，避免运动模糊；
5. **放置确认**：下视检测物料底面轮廓 vs 环心偏差 → 估算压线环级（1~6），生成放置事件给统计显示。

### 5.6 码垛检测（第二批）

- 下视拍第一层物料顶面：确认颜色与任务码要求一致（颜色分类）；
- 放置第二层时：检测上层物料轮廓中心 vs 下层顶面轮廓中心的偏移，输出纠偏量；放置后确认"上层稳定无倾倒"（轮廓仍可见且未滑落）。

### 5.7 车道识别与循迹

- HSV 分割灰色：`S < 60`（低饱和）且 `80 < V < 220`；只处理画面下方 1/3 ROI；
- 求车道区域最大连通域质心与主轴（`fitLine` 或最小二乘拟合边界）→ 输出：
  - 横向偏差 = (质心 x − 图像中心 x) / 图像半宽（归一化 −1~1）；
  - 航向角 = 主轴与图像纵轴夹角；
- **十字路口检测**：车道区域宽度骤增（400mm 直道 → 十字交叉处连通域宽度接近画面宽度）→ 发"路口"事件给主控，由主控按路径规划转弯；
- 20Hz 持续输出，主控与编码器/陀螺仪融合。

### 5.8 障碍物检测

- 在车道掩码内找黑色连通域（V < 70），面积过滤（φ50 柱在 500mm 处约 60×100px 级，标定确定范围）；
- 取最近障碍（y 最大者），按 §6.2 地面投影模型换算距离与方位；
- 连续 3 帧确认才报警，避免地面污渍误报；障碍是静止的，主控绕行后视觉持续跟踪其方位直到脱离视场。

### 5.9 区域识别与越界预警

- 全画幅 HSV 分类统计：蓝色（启停区）、淡黄（禁入区）、灰（车道）、白（底色）占比；
- 机器人车头下方 ROI 判定"当前所在区域"，一旦非灰且非启停区 → 立即发越界告警（越界=本轮结束，**这比得分更重要**）。

### 5.10 数字识别（环心 1/2/3）

- 字体固定，直接用模板匹配（自采 3 张模板 + 多尺度匹配），比 OCR 快且稳；仅作环位校验用，识别失败不影响流程（任务码已规定位置）。

### 5.11 任务统计事件流

视觉产生的事件：`抓取成功(颜色)`、`放置完成(环级)`、`码垛成功`、`越界预警`。主控据此统计并在显示屏输出（≥12mm 字高显示装置，主控硬件负责）。

## 6. 相机标定

### 6.1 内参标定
棋盘格（9×6、格 20mm）采集 15~20 张不同位姿 → `cv2.calibrateCamera` 得内参/畸变；下视相机同样标定。标定一次即可，镜头不动不重标。

### 6.2 前视相机地面投影模型（测距）
相机高 h、俯角 θ、焦距 f 已知（标定）时：

```
地面距离 d = h · (f·sinθ + (v0−v)·cosθ) / ((v0−v)·sinθ − f·cosθ)
```
（v0 为主点纵坐标，v 为目标点像素纵坐标）。实现为查找表，避免实时三角函数。

### 6.3 下视相机手眼标定（2D 即可）
- 相机垂直向下固定：像素 → mm 只需比例尺（px/mm），一次标定；
- 求"环心像素 → 相对机器人参考点偏移"：在已知标记点（如机身中心投影点）标定相机安装偏移 (dx, dy) 与旋转；
- 相机若装在机械臂上随臂运动，则标定"末端坐标 ↔ 相机坐标"的固定变换，每次对位用当前末端位姿反算。

### 6.4 颜色标定流程
见 §5.3，每次上场 30 秒内完成，写入 config 热加载。

## 7. 性能预算与优化

| 模块 | 目标帧率/延迟 | 优化手段 |
|------|--------------|---------|
| 车道 | 20Hz，延迟<100ms | ROI 裁剪 + 640→320 缩放 |
| 障碍 | 10Hz | 与车道共用掩码 |
| 转盘跟踪 | 15Hz | 只处理转盘 ROI |
| 圆环对位 | 10Hz，单帧<50ms | 停稳后拍照，ROI 局部找圆 |
| QR | 专项模式（停稳读） | 多尺度 + 双引擎 + 1080p 单帧兜底 |
| 颜色分类 | 10Hz | 掩码 + 连通域，向量化 numpy |

通用优化：
- `cv2.setNumThreads(4)`、numpy 向量化、避免逐像素 Python 循环；
- 处理全在 ROI 上做，全画幅只用于区域分类；
- 若 Python 帧率不足：只把热点（颜色/圆检测）下沉为 C++ 扩展或直接用 `apt install python3-opencv` 的 NEON 优化版；
- 树莓派固定 `performance` 调频 + 良好散热。

## 8. 鲁棒性设计（现场最容易翻车的点）

1. **光照**：曝光/白平衡锁定 + 现场标定；场馆灯光频闪 → 曝光时间设为 50Hz 整数倍周期；
2. **色差**：所有颜色阈值来自现场采样，不硬编码；
3. **反光**：偏振片 + 环形灯扩散片；二维码板倾斜读码；
4. **运动模糊**：凡是"精确对位/确认"类任务，一律停稳后拍照；
5. **误检**：所有输出加时序滤波（连续 N 帧一致）与格式校验；
6. **丢帧/延迟**：最新帧策略 + 每帧带时间戳，主控侧做超时处理（视觉 2 秒无响应 → 主控降级为编码器兜底）；
7. **转盘停留时间未知**：停转检测 + 动态预测双模式都实现。

## 9. 调试与测试

### 9.1 实验室模拟场地清单
- 2.4m×2.4m 白底（PVC/哑光 KT 板） + 灰色车道（灰胶带/喷漆，400mm 宽十字） + 淡黄区（450×450） + 蓝色启停区（300×300）；
- φ50×100 黑色圆柱若干；A4 二维码板（打印任务码二维码，用同一套编码规则生成）；
- 转盘：减速电机 + 调速，模拟 6~10s/圈与随机停留；3D 打印同规格 6 色物料（重点打浅蓝 PLA）；
- 580×150 圆环板：按 φ1~φ6 公式 + 1.5mm 线宽打印贴膜，环心标数字 1/2/3。

### 9.2 离线回放测试（强烈建议）
相机录制各类场景视频 → 视觉程序加"文件输入"模式回放 → 用同一批视频回归测试算法改动。这比反复开机上场地效率高一个数量级。

### 9.3 比赛现场 3 分钟调试清单（按序执行）
1. 开机自检：双相机出图、串口握手；
2. 曝光/白平衡锁定确认（看直方图）；
3. 颜色标定（自备 6 色色卡 + 现场物料）；
4. 转盘圆心标定（拍一张转盘静止图，人工点圆心）；
5. 圆环检测参数微调（拍一张目标区图）；
6. 试跑一键启动 + 读码 + 显示。

### 9.4 日志与可视化
- 所有判定存日志（时间戳、命令、结果、置信度、耗时）；
- 关键帧存盘（读码帧、放置确认帧），赛后复盘；
- WiFi 推 MJPEG 流到笔记本浏览器（`http://<pi>:8080/stream`），**只推不控，合规**。

## 11. 风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| 现场光照与实验室差异大 | 颜色/车道全部失效 | 现场标定流程 + 曝光锁定 + 阈值热加载 |
| 转盘停留规律未知 | 抓取失败 | 停转检测与动态预测双模式 |
| QR 反光/距离不对 | 拿不到任务码（全盘皆输） | 双引擎 + 多尺度 + 主控位姿重试循环 |
| 下视相机对位偏差 | 放置丢大分 | 手眼标定 + 闭环逼近（≤2mm）+ 停稳拍照 |
| 15 秒静止判负 | 白等转盘被判负 | 视觉发"等待中"信号，主控微动蠕动 |
| 越界（进黄区/白区） | 直接结束 | 区域分类实时预警，优先级最高 |
