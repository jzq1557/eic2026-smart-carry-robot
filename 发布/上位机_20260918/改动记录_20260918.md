## 一、place_demo.py —— 加工区「放置」调试器（改动最大）

### 1. 工序顺序纠正（车主原话："瞄准 → 归零 → 去 123 号置物架夹取 → 回来放"）

**旧（错）**：`回作业位 → 夹料 → 瞄准 → 放置` —— 瞄准出来的偏移**根本没被用上**。

**新（对）**：`回 90° 作业位 → 瞄准标靶 → 归零 → 去物架夹料 → 回放到靶心 → 放置`

与 `aim.py` 里现场验证过的 `place_mission()` 同构：
`converge → replay(off,-1) → BUILTIN_GRAB_VEH → replay(off,+1) → BUILTIN_PLACE`

### 2. 新增两个按键（对应那两次 replay）

| 键 | 作用 |
|---|---|
| `a` | 瞄准标靶，**记住本次偏移 off** |
| `z` | **归零** `replay(off,-1)`：把 base/伸缩还回去 → 夹料的确定起点 |
| `P` | 从 n 号物架夹料（动作组自带回 90°、净高度 0） |
| `b` | **回放** `replay(off,+1)`：补回 off → 回到刚瞄好的靶心 |
| `0` | 放置：下放 → 松爪 → 抬回 |

`z`/`b` 带**状态机**（`none/aimed/zeroed/backed`），重复按会被拦下
（否则多按一次 `z` 会再 replay 一遍，白转一个 off）。
`P` 前没归零、`0` 前没回放，都会打警告。

### 2b. ★已修 bug：按 `B`（绿色一条龙）被 `b`（回放）抢走

**症状**（车主现场）：按 `B` 报
`!! 没有『待回放』的偏移（状态=none）` —— 绿色靶位根本进不去。

**根因**：菜单里 `c = p[0].lower()`，所以 `"B"` → `"b"`；
而 `elif c in ("b", "back")` 排在 `elif p[0] in ("A","B","C")` **前面**
→ 大写 `B` 永远命中"回放"分支。

**为什么只有 `B` 中招**：`a` 分支写了 `and p[0] not in ("A","B","C")`、
`c`/`couple` 分支也写了 —— 唯独新加的 `b` 分支忘了加。
（`A`→`a`、`C`→`c` 都被排除条件救下来了，只有 `B` 漏网。）

**修法**：`elif c in ("b", "back") and p[0] not in ("A", "B", "C"):`

**规律**：本函数里凡是**小写**命令分支（`a` / `b` / `c` …），都必须照这样排除
`p[0] in ("A","B","C")`，否则大写一条龙会被抢先命中。

**验证**（板下沙盒 dry-run）：`B` → `[2号靶] 瞄准 2 号靶位（标靶颜色 = green）` ✓、
`A` → 红 ✓、`C` → 蓝 ✓、小写 `b` 的回放链路 ✓ 无回归。

**菜单完整顺序**：`l → a → z → P → b → 0`；或直接 `A`/`B`/`C` 一条龙。

### 3. ★自带一份动作参数（车主："两个程序内容还是不太一样，不能直接链接变量"）

旧写法 `from grab_demo import RACK_LIFT_UP, ARM_IN_VEL, BASE_90 …` = **两边共用同一个变量**，
在 grab_demo 里改一个值，place_demo 偷偷跟着变，现场分不清谁在动。

现在：
- 参数区新增 **"0. 本文件自带的一份动作参数"**，含
  `BASE_90 / TTL_VEL / RACK_WORK_DEG / RACK_TURN_DEG / RACK_LIFT_UP / RACK_LIFT_DOWN /
   RACK_LIFT_CLEAR / RACK_LIFT_BACK / RACK_ARM_IN / RACK_TTL_VEL / RACK_HOME_BEFORE /
   LIFT_*_VEL / ARM_*_VEL / GRIP_* / CHASSIS_* / INIT_STEPS / PLACE_DOWN / PLACE_UP`，
  还自带 `_deg2pulses()`
- `import` 只剩**函数**：`build_car, aim_and_track, rack_zero, _run_rack, goto_base_deg,
  jitter_test, couple_calib, manual, show_aim, show_steps, as_code`
- 四个辅助函数全部**显式传参**（`base90= / ttl_vel= / work_deg= / turn_deg=`）
- 菜单 `p` 会打印这份备份，方便与 grab_demo 逐行对照

### 4. 标靶颜色（与市赛不同）

## 三、★TTL 单轴估时补上「加减速段」（修"伸缩没到位就动龙门/夹爪"）

**现场现象**：去物架夹取时，伸缩台还没到位，龙门架下放 + 夹爪闭合的命令已经发出去了。

**根因链**：
- 固件 `TTLctrl.c`：`0x10/0x11/0x12` 是**非阻塞**的（"单轴非阻塞控制…发完即返回,不等待"）
  → 上位机只能按时间估；
- 固件 `car_config.h`：`TTLCTRL_ACC_DEFAULT = 60`（非 0 → **带加减速**）；
- 老公式 `脉冲×60/(RPM×3200)` **只算匀速段**，漏了加速段和减速段。

**误差随速度放大**（6500 脉冲伸缩）：

| 速度 | 匀速段 | 加减速段 | 真实耗时 | 老公式只等 | 结果 |
|---|---|---|---|---|---|
| 40 RPM | 3.05s | ~0.27s | ~3.3s | 3.30s | ✅ 看不出 |
| **200 RPM** | **0.61s** | **~1.33s** | **~1.9s** | **0.86s** | ❌ 少等 1.3 秒 |

**修法**：
- `school_config.py` 新增 `TTL_ACC_RPM_PER_S = 300`（加减速斜率 RPM/s）、`TTL_TIME_EXTRA_S = 0.25`
- `car.py` 新增 `ttl_time()` / `ttl_wait()`：
  `总时间 = 脉冲×60/(RPM×3200) + 2×RPM/TTL_ACC_RPM_PER_S + 余量`
- `route_car.py` 的 `_wait_axis` 改走同一套（它原来也复制了老公式）
- 每次动作打印分解：`等到位 ≈ 2.19s（匀速 0.61 + 加减速 1.33 + 余量 0.25）`

**现场标定法**（若还嫌不准）：量一次大行程实际时间 T，则
`斜率 ≈ RPM ÷ ((T − 匀速段) ÷ 2)`；**值越小 = 等越久 = 越安全**。

## 四、参数变更一览（现场值）

| 参数 | 旧 | 新 | 谁改的 |
|---|---|---|---|
| `RACK_LIFT_DOWN` | 1000 | **300** | 现场 |
| `RACK_LIFT_CLEAR` | 300 → (8000) | **800** | 现场一度误输 8000，车主定稿 800 |
| `PLACE_DOWN` / `PLACE_UP` | 2400 | **3500** | 现场 |
| `GRIP_OPEN_ANGLE` | 50 | **20** | 现场 |
| `RACK_TURN_DEG` | {1:60,…} | **{1:55, 2:90, 3:125}** | 车主确认 |
| `ARM_IN_VEL` / `ARM_OUT_VEL` | 40 | **200** | 现场 |

### ⚠️ 关于那次 8000 的误输（值得记一笔）

`RACK_LIFT_CLEAR = 8000` 会使 `RACK_LIFT_BACK = 300−2800−8000 = −10500`：
- **高度账仍然是平的**（净 0），所以程序不报错、也看不出来；
- 但**中间高度**会跑到 `H+10500` 脉冲 ≈ 3.3 圈，而龙门正常只走 2800
  → **第一步就顶死限位**。

**教训**：`RACK_LIFT_BACK` 是**算式**，改它上游任何一个参数都会连带改变
`_back_steps()` 的方向和大小。改完务必用菜单 `p` 看一遍**实际脉冲**，别只看算式那几行。

- 菜单 `A/B/C` 跑完的 `aim_state` 从 `backed` 改成 `none`（已经回零了，没有待回放的偏移）
