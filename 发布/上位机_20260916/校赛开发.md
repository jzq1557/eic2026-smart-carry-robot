## 0. 与市赛的差异速览（先看这张表）

| 维度 | 市赛（原） | 校赛（魔改） | 影响 |
|---|---|---|---|
| 物料获取 | **转盘**转动到取料位 | **地面固定三个位置**，车平移过去取 | 不再需要转盘控制；改为底盘定位 + 视觉确认 |
| 物料种类 | 6 色（红黄蓝绿黑浅蓝） | **只有红/绿/蓝三色**，固定编号 1/2/3 | 颜色识别只需 3 类，阈值更稳 |
| 任务码 | 4 组三位（15 字符） | **两段：前段抓取顺序 + 后段放置顺序**（如 `123+321`） | 解析逻辑简化，但语义要分清 |
| 扫码时机 | 上车后 | **出启动区 → 前进 → 侧装摄像头扫码**（运动中监听） | 需要"边移动边扫"或"到位后扫" |
| 放置映射 | 按环分/颜色规则 | **物料 3→加工区 1 位、2→2 位、1→3 位**（交叉） | 放置顺序 ≠ 位置顺序，要单独算 |
| 加工区 | 靶心若干 | **三个标靶沿纵深固定间隔** | 三次放置要分别瞄准 |
| 结束动作 | — | 前进 → **向右长距平移** → 停 | 需要精确的长距平移（走里程，不靠视觉） |

## 1. 规则完善版（可执行规格）

> ⚠️ 标 **[待确认]** 的是我按现有信息做的合理假定，现场/赛前必须核对；代码里都做成了**配置项**，改配置即可，不用改代码。

### 1.1 场地与区域（以车头初始朝向为 +X 前方）

```
        ↑ 前方(+X)
   ┌──────────────────────────────────────────────┐
   │  [启动区]                                     │
   │     │ ①右移出区 ②前进                          │
   │     ▼                                          │
   │  [扫码位]  ← 侧装摄像头朝左/右扫墙上的二维码     │
   │     │ ③前进                                    │
   │     ▼                                          │
   │  [原材料区]  左侧贴边，物料沿纵深排列：          │
   │     位1 ── 位2 ── 位3   （间隔固定） [待确认]    │
   │     │ ④按扫码顺序取料（每次 base 左转 90° 作业） │
   │     │ ⑤前进 ⑥原地自旋 90° ⑦前进                 │
   │     ▼                                          │
   │  [加工区]  左侧贴边，标靶沿纵深排列：            │
   │     靶A ── 靶B ── 靶C  （间隔固定） [待确认]     │
   │     │ ⑧三次 瞄准→取料→放置                      │
   │     │ ⑨前进 ⑩向右长距平移                       │
   │     ▼                                          │
   │  [结束位]  停                                   │
   └──────────────────────────────────────────────┘
```

- **车与料区的关系**：车**左侧朝向料区**，机械臂 Home 在车辆正前方 → 作业前 **base 轴左转 90°**，
  之后机械臂伸向车的左侧；三个位置**沿车的纵向前后排列**，用底盘前后移动（+base 微调）逐个对齐。
- **[待确认] 位置编号方向**：物料"位1/位2/位3"沿车前进方向的物理顺序（默认 1→2→3 递增）。
  代码里是 `layout.material_positions`（各位置的纵向坐标），取料顺序只由扫码决定，
  移动方向由坐标差自动决定（前进或后退都支持），所以**即使方向猜错也只是改一行配置**。
- 场地尺寸/间距沿用市赛 2400×2400 灰色车道（400mm 宽、两侧 50mm 余量）；物料 ≤300×300×400mm，
  单车单电池不可更换，显示屏 ≥12mm，只允许垂直补光。

### 1.2 物料与颜色（固定绑定，硬编码在配置里）

| 物料编号 | 颜色 | 原料区初始位置 [待确认] | 车上物架 slot |
|---|---|---|---|
| 1 | 红 | 位1 | 取料顺序第 1 个 → slot 1 |
| 2 | 绿 | 位2 | 取料顺序第 2 个 → slot 2 |
| 3 | 蓝 | 位3 | 取料顺序第 3 个 → slot 3 |

> **车载账本**：上位机每夹一个物料就记一条 `物料编号 → 物架 slot`（`ledger`），
> 放置阶段靠它反查"要放 3 号料，它在 slot 几"。这是本赛制最容易搞错的地方。

### 1.3 任务码语义（`ABC+DEF`，如 `123+321`）

| 段 | 含义 | 例（123+321） |
|---|---|---|
| 前段 `ABC` | **取料顺序**（按物料编号，对应三个固定位置） | `1→2→3`：先去位1取红，再位2取绿，最后位3取蓝 |
| 后段 `DEF` | **放置顺序 + 目标**：数字=颜色编号，先后=放置先后 | `3→2→1`：先放蓝(3)→加工区1位；再放绿(2)→2位；最后放红(1)→3位 |

**放置目标映射**（写死，配置可改 `placement_map`）：`物料3→靶A(1位)`、`物料2→靶B(2位)`、`物料1→靶C(3位)`。

⚠️ 关键推论：**放置顺序 ≠ 目标位置的物理顺序**。上面例子要按 A→B→C 依次放（因为放置顺序是 3、2、1，
刚好对应 A、B、C）；但若任务码是 `123+123`，放置顺序是 1、2、3 → 目标位置是 3、2、1（C→B→A），
车要**先跑到最远处再退回来**。主程序必须支持"前后移动 + 逐个瞄准"，而不是死板地一路向前。

### 1.4 全流程状态机（M0~M10）

| 状态 | 动作 | 判据/输出 | 超时 |
|---|---|---|---|
| M0 `IDLE` | 等发车；检查下位机在线 + 参数已同步 | 收到启动 | — |
| M1 `LEAVE_START` | **右移**出启动区 → **前进**到扫码位 | 里程到位 | 8s |
| M2 `SCAN_QR` | 监听侧装摄像头，解出任务码 | 得到 `ABC+DEF` | 10s（超时用默认码并告警） |
| M3 `TO_MATERIAL` | 前进到原料区作业线；**base 左转 90°** | 到位 | 10s |
| M4 `PICK_LOOP` | 按 `ABC` 依次：移动到该位 → **瞄准(G1/G2/G3)** → 夹取 → 记账本 | 3 个物料全部上车 | 90s |
| M5 `TO_PROCESS` | 前进一段 → **原地自旋 90°** → 前进进加工区 | 到位 | 12s |
| M6 `PLACE_LOOP` | 按 `DEF` 依次：算目标靶位 → 移动到靶前 → **瞄准(P1/P2/P3)** → 回物架夹料 → 回放偏移 → 放料 | 3 个全部放完 | 150s |
| M7 `TO_FINISH` | 前进一段 → **向右长距平移** → 停 | 到位 | 15s |
| M8 `DONE` | 停、回 Home、置"完成"标志（供裁判/显示屏） | — | — |
| M9 `ABORT` | 任意环节超时/失败：停下 + 记录断点 + 可选重试一次 | — | — |

### 1.5 死线与判罚（沿用市赛精神）

- **静止 15s 判负** → 每个动作原语都必须带超时；主循环有"静止看门狗"（`flow_runner.py` 里已有）。
- 越界/压线/碰倒物料：按现场裁判；程序侧只保证"沿车道中线走 + 到位才动作"。
- 一次发车，中途不得人工干预（除了规则允许的复位）。

## 2. 六次瞄准 —— 本赛制的核心动作

| 编号 | 阶段 | 目标 | 流程 | 关键差异 |
|---|---|---|---|---|
| **G1/G2/G3** | 原料区取料 | 物料中心（圆环/圆形物料） | 移动到位 → 视觉锁定 → **分轴 PID 收敛** → 夹取 → 记账本 | **直接抓**：不需要归位/回放，瞄上就夹 |
| **P1/P2/P3** | 加工区放置 | 标靶圆环中心 | 移动到位 → **瞄准并记录偏移** → 归位 → 从车载物架夹取对应物料 → **回放偏移** → 放料 | 完整 mission：瞄 → 取 → 放（= 原 `aim_and_place.py --mission`） |

**为什么抓取和放置不对称**：取料时物料就在车上夹爪能到的地方，瞄上即夹；
放置时车上物料在**物架**上、不在夹爪里，必须先记录"观察位→靶心"的净偏移，再回去夹料，最后按偏移回放到靶心。

**G 与 P 共用同一套视觉与 PID**（`aim.py`），只有"succeed 之后的动作序列"不同（由配置里的动作组名决定）。

### 3.1 分工原则（一句话版本）

> **下位机 = 一个"哑"运动执行器 + 参数表**：只提供 `Move*/Act*` 空接口，速度、脉冲、加速度、
> 动作组步骤**全部由上位机在初始化时下发**；**上位机 = 大脑**：任务码、路线、视觉、瞄准、动作组全在这里。

| 层 | 放在下位机的 | 放在上位机的 |
|---|---|---|
| 运动学 | 定时器脉冲生成、斜坡加减速、限位保护 | 走多远/走多快/加速度多少（下发） |
| 动作组 | **解释器**：按上位机下发的步骤表逐条执行 | **动作组定义**：`motion_profile.json` 里写步骤 |
| 闭环电机 | TTL 帧收发（Emm_V5 协议）、回执 | 目标角度/距离（下发） |
| 视觉 | 无 | 圆环定位、颜色识别、二维码、瞄准 PID |
| 决策 | 无（只回执 + 状态） | 状态机、任务码解析、账本、异常兜底 |

### 3.1b 本车机械结构（2026-09-16 车主确认 —— 写代码前先看这张表）

| 部位 | 实现 | 协议 | 单位 |
|---|---|---|---|
| 伸缩滑台 | TTL 闭环 **id1** | `0x10` | 脉冲 / RPM |
| **龙门架升降** | **TTL 闭环 id2 + id3，两台反向传动** 带动 | `0x11`（内部自动 id2=dir、id3=反向） | 脉冲 / RPM |
| base 轴 | TTL 闭环 **id4** | `0x12` | 脉冲 / RPM |
| 夹爪 | **舵机 Servo2**（PA2 / TIM5_CH3）：`SERVO_GRIP_OPEN=50` 张 / `SERVO_GRIP_CLOSE=82` 夹 | `0x14` 开闭、`0x15` 任意角度 | **角度 0~255°** |
| 腕关节 | **舵机 Servo3**（PA3 / TIM5_CH4）：240 朝前 / 60 朝后 | — | 角度 |
| 底盘 4 轮 | 步进 + `ramp.c` 斜坡引擎 | `0x01` / `0x02` / `0x03` | cm / 度 |

⚠️ **本车没有**独立步进升降轴、**也没有**载物台旋转电机（载物台是固定的）→ 固件 `claw.c` 里的
`Lift_GoTo / Lift_MoveBy / Tray_Turn120 / Claw_GrabFromTray / Claw_PutLayer1` 都是**老师车的遗留，本车别调用**；
固件 `protocol_and_main.c` 里的 `0x0B`/`0x0C`（升降）/`0x07`/`0x09`（转盘抓/放）同理，留着不碍事但别用。
`MOTOR1_Init / MOTOR5_Init` 这类上电初始化可以保留（不会乱动）。

> 结论：**"升降"就是龙门架**，`car.lift_up()/lift_down()` 走 `0x11` 是对的；
> 夹爪相关一律走舵机协议 `0x14/0x15`，单位是角度。

**方向约定（以固件 `chassis.c` 为准，别按直觉写）**：

| 动作 | 命令字 | 参数含义 |
|---|---|---|
| 前进 / 后退 | `0x01` X_cm | **cm ≥ 0 = 前进**，cm < 0 = 后退 |
| 左移 / 右移 | `0x02` Y_cm | **cm ≥ 0 = 左移**，**cm < 0 = 右移**（原工程注释写着"负=右, 已实测校正"）|
| 自旋 | `0x03` deg | **deg ≥ 0 = 逆时针(CCW)**，deg < 0 = 顺时针(CW) |

- 上位机侧由 `lower_api.py` 的 `_RIGHT_SIGN = -1`、`_SPIN_SIGN = {"cw": -1, "ccw": +1}` 做换算，
  所以 `car.right(30)` / `car.spin(90)` 的语义是对的；回归里有 **[0] 方向符号**专项断言把这条钉死
  （右移必须发 `0xE2 = -30`、cw 必须发 `0xA6 = -90`）。
- 帧布局是 `FF cmd b1 b2 b3 … FE` → **X 在 `f[2]`、Y 在 `f[3]`、旋转在 `f[4]`**（写断言/排查时别数错）。

### 3.2 下位机「空函数接口」清单（只做参数化执行，不写死数值）

> **实现文件**：`整机程序设计\校赛\firmware\params.c/h`（参数表）+ `motion.c/h`（动作组解释器）
> ＋ 同目录 `README_校赛扩展.md`（Keil 接入步骤 + 帧布局对照表）。
> ⚠️ 这 5 个文件**刻意不放进原 Keil 工程**（`26090901TEST\CLEAN\`），原工程保持干净、随时可编译；
> 要用校赛固件时按 `README_校赛扩展.md` 把它们 Add 进工程再 Rebuild。

```c
/* ===== 初始化（上电后由上位机下发，掉电丢失；可 0x23 存 Flash）===== */
void Params_Reset(void);                       /* 把所有参数恢复默认 */
void Params_SetU16(uint16_t id, uint16_t v);   /* 单参数：速度/脉冲上限/加速度/超时 */

/* ===== 动作步骤表（上位机下发，下位机只解释执行）===== */
void Motion_Clear(uint8_t group_id);                                 /* 清空一组 */
void Motion_AddStep(uint8_t group_id, uint8_t axis, int8_t dir,
                    int32_t pulses, uint16_t vel, uint16_t acc);     /* 追加一步 */
uint8_t Motion_Run(uint8_t group_id);                                /* 执行整组(阻塞到完成) */
uint8_t Motion_Busy(uint8_t group_id);

/* ===== 原子动作（也走参数表，不写死）===== */
void Chassis_Move_cm(uint8_t dir, int16_t cm);        /* 前后左右：距离来自参数表/入参 */
void Chassis_Spin_deg(uint8_t dir, int16_t deg);
void TTL_Move_Axis(uint8_t axis, int8_t dir, int32_t pulses, uint16_t vel);
void TTL_Home(uint8_t axis);
/* ★夹爪/腕关节是**舵机**（claw.c，Servo2=PA2 / Servo3=PA3），单位是角度 0~255°：
 *   Grip_Close/Grip_Open 用 car_config.h 的 SERVO_GRIP_CLOSE(82)/SERVO_GRIP_OPEN(50)；
 *   也可由上位机 0x15(Grip_Angle) 设任意角度，或 0x20 下发 P_GRIP_*_ANGLE 覆盖默认值。
 *   ⚠️ 改角度必须同步全局 servo_angle2/3，否则 TIM6 每秒把旧角度写回（claw.c 已处理）。 */
void Grip_Close(void); void Grip_Open(void); void Grip_Angle(uint8_t deg);

/* ===== 回执 ===== */
void Ack_Send(uint8_t cmd, uint8_t status);    /* 0xFF cmd status 0xFE */
```

> 现在的 `TTLctrl.c` 里那些 `4400 / 1700 / 6400 / 1200` 之类的魔数，全部变成"默认值 + 可覆盖"：
> 上电先用默认值，上位机 `sync` 之后一律用下发的值。

### 3.3 协议扩展（在现有 `0xFF + cmd + 7B + 0xFE` 上追加）

| cmd | 名称 | payload（7B） | 说明 |
|---|---|---|---|
| `0x20` | `SET_PARAM` | `id(2B 大端) + value(4B 大端) + rsv(1B)` | 单参数下发；回 ACK |
| `0x21` | `SET_MOTION_STEP` | `group(1B) + axis(1B) + dir(1B) + vel(2B) + acc(2B)` 加上脉冲需第二条 | 步骤表下发（脉冲 4B 单独一条 `0x21` 子类型） |
| `0x22` | `GET_PARAM` | `id(2B) + rsv(5B)` | 读回参数（校验用） |
| `0x23` | `SAVE_PARAMS` | 全 0 | 存 Flash（可选，掉电保留） |
| `0x24` | `MOTION_RUN` | `group(1B) + slot(1B) + rsv(5B)` | 执行某组（`slot` 兼容原 0x16 的物架位） |

> 5B/7B 的取舍：现有帧固定 7 字节，所以一条命令放不下的字段就**拆两条**（先 `0x21` 建步，
> 再 `0x21` 子类型补脉冲），下位机按 `group + index` 组装。实现见 §5.3。
> 兼容性：`0x13/0x16` 保留，作为"内置默认动作组"，方便没有上位机时的裸机调试。

## 4. 视觉与瞄准（结合两份 demo）

### 4.1 圆环定位（来自 `ring_center_detect_v2.py` + `ring_stream_ui.py`）

- **检测链**：`rotate_ccw → resize(处理宽) → GaussianBlur → adaptiveThreshold → 闭运算 →
  最大连通域 → 最小外接圆`（`find_center`）；
- **φ1 内径**：`find_inner_radius`（复用 `find_center` 的掩膜，`bw_full=` —— RDK 上省 ~8ms/帧）；
- **数字/形状识别**：`recognize_digit` 用 2592 张旋转模板做 NCC（`T @ g` 一次矩阵乘），
  配合**滑动窗口投票**取众数（`digit_votes=20`）；
- **稳定输出**：原始中心 → EMA 平滑（`ema=0.5`）+ 突跳清窗（`jump_px=120`）+ 丢失保持（`stale_max`）；
- **RDK 上的参数档**：`--perf rdk`（`width 512 / proc_scale 0.34 / thr_block 25 / close_k 5 /
  digit_every 3 / diag_every 20`）→ 实测 **15.8fps**（详见根 README §6.7）。

**瞄准里只用它的"中心 + 半径"**：`cx_px / cy_px / r_outer_px / conf / stale`。

### 4.2 圆形颜色识别（来自 `color_blob_demo.py` 的 `ColorBlobDetector`）

- **检测链**：降噪（暗色必须先高斯）→ 色相增幅/压制 → HSV 阈值 → 形态学 → 圆度/面积筛 → 最小外接圆；
- 校赛只需 **红/绿/蓝** 三色（`PRESETS` 里直接取），阈值现场标定后存 `color_profile.json`；
- 用途有两个：① 取料前**确认这一位是不是该取的物料**（防错位）；② 放置前**确认夹爪里的颜色**。

### 4.3 瞄准控制（提炼自 `aim_and_place.py`）

```
settle(0.4s) → 单帧检测 → 若未找到: 小步试探/等待
            → 阶段A: 只用 base(id4) 收敛画面 x
            → 阶段B: 只用伸缩(id1) 收敛画面 y
            → X2 二次复校（两轴各自再收敛一次）
            → 收敛判据: |dx|,|dy| ≤ 8px 且连续 2 帧
            → 记录净偏移(脉冲): aim_offset = {base, arm}
```

参数（**全部在上位机**，`school_config.py` / `motion_profile.json`）：

| 参数 | 含义 | 现值来源 |
|---|---|---|
| `K_PX2STEP_BASE=0.2593` / `K_PX2STEP_ARM=0.0413` | 像素→脉冲 | `calibrate_aim.py` 现场标定 |
| `CAM_GRIP_OFFSET_X/Y` | 夹爪与光轴不共轴补偿 | 现场实测 |
| `OUT_MAX_PX=30` | 单拍限幅（防冲过头） | 固定 |
| `SETTLE_S=0.4` | 停稳等待（补偿视觉延迟） | 固定 |
| `ARM_VEL=25 / BASE_VEL=40` | 闭环电机转速 | `motion_profile.json` |

### 4.4 G（抓取）与 P（放置）的差异

| | G 抓取瞄准 | P 放置瞄准 |
|---|---|---|
| 目标 | 物料外形（圆/方）+ **颜色确认** | 标靶圆环（无需颜色） |
| 收敛后 | **直接** `Grip_Close` + 抬臂 | 记录 `aim_offset` → `Home` → 物架夹料 → `replay(offset)` → `Grip_Open` |
| 失败重试 | 重新检测（最多 3 次小步试探） | 回到观察位重瞄（最多 2 次） |
| 账本 | 写入 `{物料编号: slot}` | 读取并消费（放完标记 done） |

### 4.5 现场标定清单（一次搞定，之后只调 JSON）

1. `python3 calibrate_aim.py --port /dev/ttyUSB0` → 更新 K；
2. 夹爪对准物料 → 读圆心像素 → 填 `CAM_GRIP_OFFSET_X/Y`；
3. `python3 color_blob_stream.py --perf rdk` → 三色阈值 → 存 `color_profile.json`；
4. `python3 ring_stream_ui.py --perf rdk` → 环参数 → 存 `ring_calib.json`；
5. **走一遍里程标定**：`python3 校赛/calibrate_route.py`（新工具，见 §8）→ 更新 `school_config.py`
   里的各路"前进/平移/自旋"里程（cm/度）。

### 5.3 初始化下发（回答你的 PS：**可以，而且推荐这么做**）

你的想法完全可行，标准做法叫 **"参数/动作表下发 + 下位机做解释器"**：

```python
# lower_api.py 里的同步流程（上电后、发车前跑一次，约 1~2 秒）
def sync_motion_profile(lower, profile):
    lower.set_param(P_CHASSIS_VEL, profile["params"]["chassis_vel"])
    lower.set_param(P_CHASSIS_ACC, profile["params"]["chassis_acc"])
    ...                                     # 逐个 set_param(0x20)，每个都等 ACK
    for gid, steps in profile["groups"].items():
        lower.motion_clear(gid)             # 0x21 子类型
        for i, (kind, axis, dir, pulses, vel) in enumerate(steps):
            lower.motion_add_step(gid, i, kind, axis, dir, pulses, vel)   # 0x21 ×N
    for pid in CHECKED_PARAMS:              # 读回校验（0x22），不一致就报错
        assert lower.get_param(pid) == sent[pid]
    lower.motion_save()                     # 0x23 可选：存 Flash
```

**这样做的好处**
1. 动作组迭代不用重烧固件：改 JSON → 重新 `sync` → 立刻试（现场调参效率高一个数量级）；
2. 上位机可以**按局/按赛项**切换不同动作组（校赛/市赛两套 JSON）；
3. 下位机代码变成纯解释器，可测试、可复现，不再有"魔数散落"。

**代价与规避**
- 掉电丢失 → `0x23` 存 Flash（或上电默认值兜底）；
- 下发失败风险 → **每个参数都读回校验**，失败就拒绝发车；
- 帧长限制 → 一条 7B 放不下的字段拆两条（§3.3），下位机按 `group+index` 组装。

### 6.2 主循环骨架（`school_flow.py` 里可直接跑）

```python
def run_match(lower, vision, cfg, profile):
    sync_motion_profile(lower, profile)              # ① 参数/动作组下发 + 读回校验
    lower.run_group("HOME")                          # ② 回 Home（车头朝前、臂收拢）
    lower.move("right", cfg.route.leave_start_right_cm)   # ③ 右移出启动区
    lower.move("fwd",  cfg.route.to_scan_fwd_cm)          # ④ 前进到扫码位
    code = qr_scan.listen(vision, timeout=cfg.scan_timeout)  # ⑤ 运动中监听（多帧一致才采纳）
    pick_order, place_order = parse_code(code)
    lower.move("fwd", cfg.route.to_material_fwd_cm)      # ⑥ 进原料区
    lower.run_group("BASE_TO_LEFT")                      # ⑦ base 左转 90° 进入作业姿态

    for i, mid in enumerate(pick_order, 1):              # ⑧ G1/G2/G3
        move_to_material(lower, cfg, mid)
        aim_and_grab(vision, lower, cfg, expect_color=COLOR_OF[mid])   # ★瞄准→直接夹
        ledger[mid] = i                                  # 账本：第 i 个取 → slot i
        lower.run_group("PICK_UP")

    lower.run_group("BASE_HOME")                         # ⑨ 收臂
    lower.move("fwd", cfg.route.to_process_fwd_cm)       # ⑩ 前进 + 自旋 90°
    lower.spin("cw", cfg.route.spin_deg)
    lower.move("fwd", cfg.route.enter_process_fwd_cm)
    lower.run_group("BASE_TO_LEFT")                      # 左侧朝加工区

    for mid in place_order:                              # ⑪ P1/P2/P3
        tgt = PLACEMENT_MAP[mid]
        move_to_target(lower, cfg, tgt)
        aim_and_place_mission(vision, lower, cfg, slot=ledger[mid])   # ★瞄→取→放
        stats.placed(mid, tgt)

    lower.run_group("BASE_HOME")                         # ⑫ 收臂
    lower.move("fwd", cfg.route.to_finish_fwd_cm)        # ⑬ 前进
    lower.move("right", cfg.route.finish_right_cm)       # ⑭ 向右长距平移
    lower.stop(); display.show_done(stats)               # ⑮ 停 + 上屏
```

### 6.3 异常与兜底

| 情况 | 处理 |
|---|---|
| 扫码超时/解不出 | 用默认码并**大声告警**（显示屏红字），流程继续（比卡死强） |
| 瞄准连续 3 次不收敛 | 小步试探 → 仍失败则跳过该位并记录（尽量拿部分分） |
| 动作组超时（>25s） | 判下位机异常 → `ABORT`，停 + 记录断点，允许一次复位重试 |
| 颜色不符（取错料） | 放回原位重取（最多 2 次），账本不写 |
| 任何环节 > 死线 | 走"最小完赛路径"：直接去结束位停车 |

所以**跑它的时候不要再跑 ring_stream_ui / color_blob_stream**（会抢相机）；
标定完关掉调参台，再开监控台。

## 8. 里程碑与风险

| 阶段 | 内容 | 完成判据 |
|---|---|---|
| W1 | 参数/动作组下发链路（0x20/0x21/0x22）跑通 | 上位机 `sync` 后读回值全部一致 |
| W2 | 里程标定（前进/平移/自旋/间距） | 连续 3 次到位误差 < 15mm |
| W3 | G 抓取瞄准（含颜色确认） | 3 个位置各 5 次成功 ≥ 4 |
| W4 | P 放置 mission（瞄→取→放） | 3 个靶位各 5 次成功 ≥ 4 |
| W5 | 全流程联调 + 异常兜底 | 连续 3 场不掉链子，总时长 < 死线 80% |

**主要风险**
1. **RDK 算力**：15.8fps 够"停稳再拍"，但**不够运动中跟踪** → 本方案设计成"到位后瞄准"，不做动态跟踪；
2. **里程漂移**：底盘 4 轮 + 无编码器反馈时，长距平移（结束区 120cm）误差会累积 → 用"分段走 + 时间兜底"，
   必要时加地标（视觉）粗定位；
3. **扫码时机**：侧装摄像头在移动中容易糊 → 采用"减速→低速通过→多帧一致"策略，或到位停稳再扫（多花 2s 换稳定）；
4. **下游改动风险**：固件改动**本机无 Keil 无法编译验证**，必须在你那边 Rebuild + 架空试跑（见 §9）。
